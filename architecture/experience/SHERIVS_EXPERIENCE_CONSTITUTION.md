# Sherivs Experience Constitution

## Laws

1. **Brand law.** Customer-facing product name is Sherivs. Scholar is a runtime. Jarvis is executive intelligence. CoreGrid is the kernel/engineering name.
2. **Honesty law.** No fake customers, metrics, social proof, jobs, posts, or AI activity.
3. **Runtime neutrality.** Signing in does not imply Scholar. Navigation is capability-driven.
4. **Shell ownership.** Platform owns chrome. Runtimes contribute destinations; they do not own the header.
5. **UI is not security.** Hidden nav is not authorization. Command palette cannot grant.
6. **Canonical truth.** Observation, inference, recommendation, action, evidence, and verification stay distinct.
7. **Empty stays empty.** Missing catalogs render empty states.
8. **Glass is not the brand.** Translucency is a layering tool.
9. **Motion represents state.** No decorative “thinking” without a backend.
10. **Reduced motion is a right.** `prefers-reduced-motion` and account preference both apply.
11. **Tenant brand is an overlay.** It cannot destroy contrast, focus, or Sherivs usability.
12. **Internal is a boundary.** Super-admin / Sherivs ops never appear in tenant navigation.

## Visual quality gate

Do not declare an experience complete if it could belong to generic SaaS, if hierarchy is unclear, if it fails keyboard/reduced-motion/empty/error/unauthorized, or if it only works for Scholar.

## Review gates

IA → interaction → visual → responsive → accessibility → performance → security → implementation → tests → human visual review → architecture conformance.
