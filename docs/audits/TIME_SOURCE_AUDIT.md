# TIME_SOURCE_AUDIT — J-023 time-source discipline (MISSION H2-23)

**Date:** 2026-10-02
**Mission:** H2-23 — Enforce time-source discipline (J-023): single authoritative clock, monotonic ordering.
**Role:** Temporal Integrity Engineer
**Authority contract:** `frontend/src/lib/kernel/time-authority.ts` (untouched — the contract module itself was audited, not modified).
**Scope:** `frontend/src/lib/**` production code (`.ts`, excluding test files). Test files, `tests/**`, and non-lib surfaces are out of scope for the correction mandate.

---

## 1. Method

1. **Sample definition.** A *direct wall-clock sample* is `Date.now()` or a bare argument-less `new Date()` in production code. Parenthesized conversions (`new Date(value)`, `new Date(Date.parse(...))`, `new Date(ms * 1000)`) are **not** samples — they re-derive a `Date` from an already-captured instant and introduce no new clock reading. Comment/doc mentions of `Date.now()` are not samples. The scan strips comments and string/template literal text (keeping `${...}` interpolation bodies, which execute) before matching, so documentation references cannot mask or fake a violation.
2. **Scan.** Recursive scan of `frontend/src/lib`, one inventory entry per production file with ≥1 direct sample. **Result at audit time: 96 files, 258 call sites.**
3. **Verdicts**, per the authority's own law ("the authority is the ONLY place a wall clock is sampled"):
   - **AUTHORITY-SITE** — `kernel/time-authority.ts` itself; `SystemClock.nowMs()` is the one sanctioned sample site.
   - **VIOLATION (CORRECTED)** — a server-side production module sampling the wall clock directly; **corrected** by composing the kernel authority.
   - **SANCTIONED** — residual sample with a recorded per-file rationale below (client-bundle boundary and/or an explicit caller-injection seam).
4. **Client-bundle boundary rule.** `kernel/time-authority.ts` is a node-runtime contract (top-level `import { createHash } from "node:crypto"`, which this mission may not touch). Any module reachable from a browser bundle therefore cannot top-level-import the authority without dragging a node builtin into the client build. Such modules are verdicted SANCTIONED with the boundary rationale and queued for a browser-safe authority shim (a follow-up that must land inside `kernel/time-authority.ts` or a new kernel sibling — outside this mission's file ownership).

## 2. Correction applied (composition only — no behavior change)

Every server-side violating file received the identical composition:

```ts
import { SystemClock, TimeAuthority } from "<relative>/kernel/time-authority";

/** J-023: time enters only via the kernel time-authority — no direct wall-clock sampling. */
const timeAuthority = new TimeAuthority(new SystemClock());
```

- `new Date().toISOString()` → `timeAuthority.now().at` (same ISO-8601 UTC format),
- `Date.now()` → `timeAuthority.now().atMs` (same epoch-milliseconds number),
- bare `new Date()` → `new Date(timeAuthority.now().atMs)`.

Every emitted value keeps its exact pre-correction shape and semantics (the authority issues from `SystemClock`, whose sample is the same `Date.now()` reading), so **no caller observes a behavior change**; what changes is provenance: every stamp now carries issuance sequence + issuer and is monotonic under clock regression, and no production module samples the wall clock outside the authority. Module-scoped instances keep signatures untouched — callers that already injected deterministic time still take precedence over the authority-backed defaults.

## 5. Residual risk / follow-ups

- **Browser-safe authority shim.** The 22 SANCTIONED files sit on the client-bundle boundary class. A browser-safe clock/issuance shim (no `node:crypto`) inside the kernel would let them adopt the same composition. Until then their stamps carry no issuance provenance; none of them orders consequential state by the wall reading alone (rationales above).
- **Authority fan-out.** Corrected files hold module-scoped `TimeAuthority` instances; the total order `(atMs, sequence, issuer)` is authoritative per issuance, and cross-module ordering remains well-defined because every stamp is monotonic and the wall coordinate is the first total-order key. A single process-wide authority singleton arrives with the durable substrate (per the contract's own boundary note).
- **Concurrent-mission churn.** `runtime/scholar/provisioning.functions.ts` was rewritten by mission V1-013 after correction: its final wall-clock sample (the generated-password year salt inside the retired `defaultAdminPassword`) left the codebase with that constant, so the file now carries zero direct samples and its SANCTIONED row was retired on re-scan. The mh-23 static test guards the whole classification, so any regression re-introducing a raw sample into a corrected file fails CI.
