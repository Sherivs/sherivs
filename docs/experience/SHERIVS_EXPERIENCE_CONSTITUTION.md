# SHERIVS Experience Constitution

Version: V1 foundation (2026-10-08) · Classification: **V1**
Authority: governs all Sherivs experience work; subordinate to repository
`AGENTS.md` and security invariants.

## 1. What Sherivs feels like

A coherent technological environment — institutional-grade, calm, precise,
authoritative. Reality → intelligence → action → evidence, visible in that
order on every consequential surface.

## 2. Quality bar (all must hold before "complete")

- Distinctive information architecture; hierarchy understood at a glance.
- Premium typography; controlled translucency with purpose; no visual noise.
- Meaningful motion only; full keyboard operation; honored reduced-motion.
- Works with real data, zero data, loading, failure, no permission, and for
  every organization type — not just Scholar.
- Responsive at 360 / 390 / 430 / 768 / 1024 / 1280 / 1440 / 1600 / 1920 /
  2560+ without merely shrinking desktop.

## 3. Prohibited unless architecturally justified

Generic gradient hero · random glass cards · endless card grids · giant fake
statistics · generic glowing AI orb · meaningless particles · template nav ·
generic dashboard · generic SaaS footer/pricing/testimonials · fake logos,
customers, metrics, live data, social proof. Cards are one layout tool among
many (list, table, timeline, panel, split view, command interface) — chosen
by information architecture, never by default.

## 4. Honesty law

Only ship pages for capabilities that exist. Never fabricate claims,
customers, numbers, accounts or activity. Social row renders only with
verified accounts. AI "thinking" animations require real backend processing.
Analytics show governed data or nothing.

## 5. System laws

- **Tokens**: use `--sherivs-*` / existing tokens; no one-off values without
  justification (`SHERIVS_DESIGN_SYSTEM.md`).
- **Icons**: `sherivs-icons.ts` only (lucide, 1.5px stroke).
- **Motion**: state communication only (`SHERIVS_MOTION_SYSTEM.md`).
- **Accessibility**: WCAG 2.2 AA gates every release
  (`SHERIVS_ACCESSIBILITY_SYSTEM.md`).
- **Responsive**: mobile is its own IA (`SHERIVS_RESPONSIVE_SYSTEM.md`).
- **Content**: structured types + review dates
  (`SHERIVS_CONTENT_ARCHITECTURE.md`).

## 6. Review gates

Information architecture → interaction → visual → responsive →
accessibility → performance → security → implementation → automated tests →
human visual review → architecture conformance. A gate failure returns the
surface to its mission; "premium-looking" never overrides a failed gate.

## 7. Mission discipline

Work executes as missions with owner, scope/non-scope, contracts, acceptance
criteria and test/accessibility/performance/security/evidence/rollback plans.
No mission redefines architecture; frozen V2/V3 scope is proposal-only.

## 8. Definition of done

Architecture + implementation + security + tests + documentation +
observability + operations. Claims without version-target classification
(V1 / V2_FROZEN / V3_FROZEN / FUTURE_UNASSIGNED) are unverified.
