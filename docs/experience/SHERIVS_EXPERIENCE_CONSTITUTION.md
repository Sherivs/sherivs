# Sherivs Experience Constitution

This is the rule set for experience work. A screen that violates it is not done, even if it renders.

## Laws

1. Sherivs is the customer-facing brand. CoreGrid identifiers stay where systems already depend on them.
2. An installed runtime is not the platform. Copy must not say the platform is Scholar.
3. Sign-in resolves membership. It does not assume an education workspace.
4. Verified records and derived intelligence stay distinct. Observation, inference, recommendation, action, evidence, and verification are different states.
5. AI output is untrusted until validation, policy, and, where required, approval.
6. Navigation is capability-driven. A command surface is not a policy bypass.
7. Education-only public sections appear only when the education runtime is installed.
8. The internal Sherivs workspace is not a customer tenant and is not linked from public navigation.
9. Do not invent customers, metrics, testimonials, social accounts, uptime figures, or legal instruments.
10. Empty is a valid state. A shelf with no documents says so.
11. Glass is a material for layering, not the identity. The public site is paper and ink.
12. Motion communicates state and respects `prefers-reduced-motion`. Do not animate thinking when nothing is processing.
13. Tokens are the source of color, type, space, and motion. One-off palettes need a written reason.
14. The UI is not the security boundary.

## Design review gates

A major experience is not complete until these have been answered with evidence:

1. Information architecture — can a person tell what the page is for from its order of sections?
2. Interaction — does every control go somewhere real?
3. Visual — does it use the Sherivs materials, or a generic card grid?
4. Responsive — was it considered at phone, tablet, and desktop widths, not only scaled?
5. Accessibility — keyboard, focus, names, contrast, reduced motion?
6. Performance — is the route static where it can be, without decorative weight?
7. Security — can this surface leak another tenant or the internal workspace?
8. Implementation — does it consume governed data, not an ad hoc object?
9. Tests — is the contract asserted?
10. Visual review — did a human or a screenshot review look at it?
11. Architecture conformance — V1 only, runtime neutrality preserved?

## Prohibited unless a real object requires them

Generic gradient heroes, glass as the default surface, endless card grids, invented statistics, glowing orbs, particle fields, fake logos, fake live data, template testimonials, and a pricing table that grants entitlements.

## Definition of done

Architecture, implementation, security, tests, documentation, and an honest status. A partial surface is reported as partial.
