## Implemented

- `scripts/verify-secrets-hygiene.mjs` — offline static scanner for committed secret-shaped strings, with five detection classes:
  - `PROVIDER_KEY_PREFIX` — OpenAI/Stripe/AWS/GitHub/GitLab/Slack/Google/NVIDIA key shapes, with a required word-boundary (so identifiers like `risk-…` that merely contain the substring `sk-…` do not false-positive).
  - `JWT_TOKEN` — three-segment base64url JWT shape.
  - `HIGH_ENTROPY_ASSIGNMENT` — long (≥32 chars) high-entropy literal assigned to a secret/token/key/password-like name (code and JSON/YAML assignment styles; letters+digits mix required).
  - `PRIVATE_KEY_BLOCK` — PEM/OpenSSH/PGP private-key BEGIN markers.
  - `CONNECTION_STRING_PASSWORD` — DB/service URLs with embedded passwords (placeholder passwords like `pass`, `<pw>`, `${VAR}` exempted).
- Allowlist law (always applied): `tests/**` fixture zones (self-describing synthetic fakes per wave LAW 6), the scanner's own pattern file, inline `coregrid-secrets-hygiene-allow` markers, and well-known placeholder values.
- Hygiene law for the tool itself: it never emits a full matched value — output is `file:line + pattern class + a SHORT redacted prefix (≤4 chars + length)` and the redaction is scan-safe by construction (a redacted finding line re-scanned yields no findings).
- Exit codes: `0` clean, `1` findings, `2` blocked (usage/scan error), matching the wave's fail-closed exemplar family. CLI flags: `--scan-root <dir>`, `--json` (same redaction law).
- Excluded from scan: `node_modules`, `.git`, `dist`, lockfiles, binary/oversized files (>2 MB), non-text extensions.

## Known Risks

- Static shape detection only: a determined leak that does not match a documented provider shape, JWT form, private-key marker, connection-string form, or entropy heuristic will not be caught. This is a hygiene tripwire, not a proof of secrecy.
- Residual false-positive surface: any committed value that begins with a provider prefix at a word boundary and is ≥20 chars will be flagged. Run 1 flagged eight `sk-1…` occurrences in `.claude-flow/tasks/store.json`; inspection (masked, no values) showed they are task identifiers of the form `task-<epoch>…` where `sk-` occurs mid-token (preceded by a word character), i.e. true false positives. They were eliminated by adding a required word boundary to provider prefixes — regression-tested (identifiers containing `sk-…` substrings no longer flag; quoted `sk-…` values still flag) — a precision fix, not a detection weakening.
- `tests/**` blanket allowlist is per the mission definition of synthetic fixture zones; a real secret accidentally committed inside `tests/` would be missed by design of that allowlist (documented trade-off; the inline marker and allowlist structure make a targeted tightening trivial).
- `HIGH_ENTROPY_ASSIGNMENT` uses a line-oriented heuristic (≥32 chars, letters+digits, non-placeholder); it will not catch short keys or single-class keys.
