## Implemented

`frontend/src/lib/ai-gateway/egress-allowlist.ts` — the RUNTIME enforcement half of the L-T-007 egress gap: provider endpoints are reachable only through the gateway's guarded handoff, and the allowlist fails closed on unregistered endpoints.

- `EgressAllowlist` — operator-declared bindings of provider classes (vendor-neutral, §25) to provider endpoints. DENY-BY-DEFAULT: an empty allowlist denies everything; any mismatch is a typed denial, never a guess.
- Fail-closed construction (mirrors the model registry's law): non-https declarations, embedded credentials, query/fragment-carrying endpoints, IP-literal/localhost/single-label hosts, duplicate bindings, malformed path prefixes/methods, and an invalid injected clock all throw at construction — a broken allowlist can never silently permit egress.
- `decide(attempt)` — typed decision union (`verdict: "allow" | "deny"` with `EgressDenyCode`): `unparseable_url`, `non_https_scheme`, `embedded_credentials`, `unregistered_endpoint`, `endpoint_not_bound_to_provider`, `port_not_permitted`, `path_not_permitted`, `method_not_permitted`, `invalid_request`, `invalid_clock`. Host must match exactly (registered host+port), path must be the declared prefix or a child path (string-prefix siblings rejected), method must be in the declared set (default: any).
- `decideForRouting(attempt)` — the composition point with the model registry (imported READ-ONLY, never modified): egress is permitted ONLY for an invocation the registry ALLOWED, to an endpoint bound to the routed provider class. A registry deny becomes `route_denied` (registry deny code surfaced as `routeCode`); the allowlist never re-routes. Malformed routing decisions fail closed as `invalid_request` — no implicit allow.
- `guardedFetch(attempt, transport?)` — the ONLY channel through which egress happens: a denial never touches the transport; on allow it calls the injected transport (default `globalThis.fetch`) with the original URL; a transport failure is contained by error NAME only (never message/body).
- Audit ledger (§18/§29): every decision audited, append-only, deterministic FNV-1a ids, injected-clock timestamps. Records carry scheme/host/port/path/method ONLY — query strings, fragments, headers and bodies (credential carriers) are structurally excluded.
- Purity: no environment reads, no implicit network, injected clock; identical inputs produce identical decisions and audit ids.

## Security Validation

- Deny-by-default proven (empty allowlist denies all); unregistered endpoints, ports, paths, methods, schemes all typed denials.
- Fail-closed construction for every malformed declaration; broken runtime clock denies closed (`invalid_clock`) rather than proceeding unaudited.
- SSRF hardening: allowlist accepts only registrable DNS endpoint hosts — IP literals (v4/v6), localhost forms, and single-label names are rejected at construction and at decide-time.
- Secret hygiene: declared endpoints may not carry credentials/query/fragments; audit records structurally exclude query material; transport failures surface error name only; no secret values in code or tests.
- Composition guarantee proven: no egress without a registry-allowed route; no egress across provider-class bindings; no implicit allow from malformed decisions.
- Only the mandated test command was run (`npm run verify` untouched, per campaign law); no database, no network, no git commands.

## Known Risks

- The allowlist is operator-declared truth within the gateway process; it constrains code that routes through `guardedFetch`/`decide*`. Code that bypasses the gateway and calls `fetch` directly is out of this module's reach — mitigated by review/CI convention (as with the registry itself), and by the network-layer controls this mitigation composes with.
- Exact-host matching (no wildcard subdomains) is deliberately strict; a provider needing multiple hosts must declare each endpoint explicitly.
- Default method permission is "any method" unless `methods` is declared; operators should declare explicit method sets for least privilege.
