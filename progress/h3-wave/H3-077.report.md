## FINDINGS (attacks NOT contained — recorded, not fixed)

- **FINDING G-077-F1 (medium): kernel consumption-contract drift.** `runtimeDescriptorSchema` bounds
  `capabilityRefs` with `.max(MAX_CAPABILITY_REFS)` but has NO `.min(1)`, and `decideRuntimeRegistration`
  only denies UNRESOLVED refs. An install with `capabilityRefs: []` against a context with
  `knownCapabilityRefs: []` is ALLOWED — registering a zero-consumption runtime. This drifts from the
  kernel law the module itself imports read-only (`kernel/domain-manifest.ts` `validateManifest`:
  "a runtime manifest must declare at least one consumed capability"). Documented as a labeled test
  asserting current behavior; the module was NOT modified (G-060's ownership).

## Known Risks

- `registrationProvenanceSchema.requestedBy` is never cross-checked against `context.actorRef`. No
  privilege is gained (authorization uses the context exclusively, and `decidedBy` is context-derived —
  proven above), but attested provenance is spoofable, weakening §12 provenance integrity. Recommend
  G-060 add a provenance/actor consistency rule or document requestedBy as attestation-only.
- Zod's strict-object parse does not flag an own enumerable `__proto__` key as unrecognized (the
  injection is inert because only known keys are read, and tenancy is context-derived — proven contained).
  Hardening option for G-060: reject prototype-shaped keys explicitly at the parse boundary.
