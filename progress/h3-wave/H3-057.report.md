## Implemented

`frontend/src/lib/simulation-engine/contracts.ts` — a typed, fail-closed, domain-neutral CONTRACT module for the phase-37 substrate surface. Pure: no I/O, no persistence, no vendor imports (only `zod`), no secrets, offline-testable, strict TypeScript (no `any`, no `z.any()`).

Surface:
- `ScenarioDefinitionSchema` — tenant-scoped scenario with mandatory assumptions, provenance (§12), declared subject reads (opaque refs, read-only), positive horizon/run bounds, and a fail-closed `canonicalWriteback: z.literal(false)` — a scenario that claims a write path does not parse.
- `SimulationRunRequestSchema` — deterministic seed (reproducibility mandatory), horizon bound, declared purpose (§16 purpose limitation), `executionIsolation: z.literal("isolated")` (fail-closed literal).
- `SimulatedOutcomeSchema` — the §9 encoding: `origin: z.literal("derived")` admits no other value ("observed"/"canonical" fail to parse); uncertainty band, confidence in [0,1], mandatory `validUntilMs` expiry, mandatory `auditRef` (§29).
- `SimulationRunBundleSchema` + `validateSimulationRunBundle` — cross-field invariants: scenario/run/tenant consistency (tenant mismatch fails closed, §13), run horizon ≤ scenario bound and optional governed maximum, outcomes only for `completed` runs, duplicate rejection, subject-closure, inverted/expired validity, bounds containing the estimate; all issues collected as typed codes, never truncated.
- `usabilityForDecisionSupport` — clock-injected, fail-closed usability verdict with named reasons.
- `compareAgainstObservation` — read-only diagnostic; observed value is caller-supplied under its own authorization; result itself labelled `derived`; no mutation surface.
- `decideSimulatedWriteback` — the ONLY bridge toward canonical surfaces, implementing AGENTS §16/§21 (Proposal → Validation → Policy → Approval → Audit). Fail-closed ordering: unparseable → DENY; no policy → DENY; no approval → REQUIRE_APPROVAL; approval mismatched (tenant/subject), expired, or revoked → DENY; no audit destination → DENY; only then ALLOW — and ALLOW here means "may proceed to execution elsewhere under the declared policy"; this module executes nothing.

Domain neutrality (J-037): no education/domain vocabulary; only neutral primitives (scenario, run, outcome, subject, tenant, provenance, horizon, assumption, parameter, approval, audit). The module lives in its own `frontend/src/lib/simulation-engine/` subdirectory. Composes with platform primitives read-only (imports only `zod`); no sibling H3 modules imported.

## Security Validation

- Truth boundary (§9): enforced by construction — `z.literal("derived")` origin, mandatory expiry, mandatory audit ref, no write surface anywhere in the module; the writeback bridge fails closed and even an ALLOW executes nothing here.
- Tenant isolation (§13/§31): cross-artifact tenant mismatch fails closed; approvals are tenant- and subject-scoped; expired and revoked approvals fail closed.
- Purpose limitation (§16): purposeless runs do not parse; writeback requires a declared policy (decision-gate enforced).
- Auditability (§29): outcomes and writeback proposals carry audit references.
- Provenance (§12): scenarios, assumptions, and outcomes carry who/authority/when records.
- Secrets: none handled, none printed; no environment reads (asserted by test).
- No weakening of any existing test or shared file.

## Known Risks

- The module validates structure and governance invariants only; it does not execute simulations. A runtime implementation (future phase work) must reuse these contracts; drift would need a verifier pass (G-075 verifier mission exists for exactly this).
- `decideSimulatedWriteback` decisions are advisory by design — the executing domain phase must re-enforce policy/approval/audit server-side (§34: frontend is not security).
- Expiry of derived intelligence is declared, not measured; freshness policy values are caller-declared bounds, not verified model accuracy.
