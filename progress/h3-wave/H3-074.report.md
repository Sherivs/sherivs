## FINDINGS (recorded, not fixed — module is read-only for this mission)

- **FINDING H3-074-F1 (retention-bound escape — SUCCEEDS).** A record whose bounded
  retention has expired (`retention.expiresAt < now`) is still returned as `allowed` by
  `authorizedMemoryView` (with full `content`) and as `disclosed` by `evaluateAiDisclosure`
  behind a valid gate. This contradicts the module's own posture header ("…and expired
  retention all fail closed with a typed reason", contracts.ts line 22): no read surface
  compares `record.retention.expiresAt` to the injected `now`. Precise location:
  `authorizedMemoryView` and `evaluateAiDisclosure` in
  `frontend/src/lib/memory-knowledge/contracts.ts`. Suggested direction (for the owner,
  not implemented): add a retention-vs-`now` check producing a typed reason such as
  `retention_expired`.
- **FINDING H3-074-F2 (lifecycle expungement retains content — SUCCEEDS).**
  `applyLifecycleTransition(record, "expunged", revision)` on an `archived` record with an
  approval-carrying revision returns a record that STILL carries `content` — unlike
  `executeForgettingAct`, which strips it. The returned record fails the module's own
  `parseMemoryRecord` (inconsistent state), and all read surfaces contain it (parse-first
  denial), but the "forgetting is genuine" invariant is violated at the transition layer:
  the material is not stripped, only the record made unparseable.
- **FINDING H3-074-F3 (fully forged schema-valid gate accepted — SUCCEEDS at this layer).**
  A caller-fabricated but structurally valid gate is indistinguishable from an issued gate;
  `parseAuthorizationGate` accepts it and `authorizedMemoryView` opens content. Mitigating
  context: the module's documented posture is that gates are issued server-side and this
  contract is "one layer, never the only one" (AGENTS §15/§17); containment therefore
  depends on gate objects never being caller-controllable (e.g., verifying gate provenance
  at the authorization layer before invocation).
