Team: H3-015 · Role: Mission Gate Engineer (Squad B, J-gap closures) · Date: 2026-10-03

## Implemented

`frontend/src/lib/mission/gates.ts` — the evidence-bearing gate machinery for the J-026 taxonomy
(definition / security / verification / closure), which `mission-contract.ts` declares but
explicitly defers to MISSION-R-51 ("gate machinery with evidence-bearing waivers is MISSION-R-51
and is NOT built here"). Pure contracts + validation + evaluation; no persistence, no I/O, no
vendor imports, no wall-clock reads (the caller supplies tenant, instant, and evidence ledger).

Fail-closed laws, all machine-enforced:

- **Two outcomes only.** `GATE_OUTCOMES = ["PASSED", "BLOCKED"]`; `GateVerdict` is a closed union.
  Every non-allow path is BLOCKED with machine-stable named reasons (`invalid_evaluation_context`,
  `cross_tenant`, `not_yet_effective`, `expired`, `submission_mismatch`, `future_submission`,
  `missing_evidence_kind`, `waiver_mismatch`, `waiver_not_yet_granted`, `waiver_expired`,
  `waiver_void`, `waiver_misplaced`, `undeclared_gate`, `kind_mismatch`, `duplicate_submission`,
  `closure_incomplete`).
- **A gate can never default to PASSED.** `GatePassed` carries a module-private runtime symbol
  brand (`gatePassedBrand`, never exported): only `evaluateGate` can mint a PASSED verdict, after
  requirements were actually verified. A forged literal is a compile-time error (proven by an
  `@ts-expect-error` probe, which tsc confirms is a live error). No code path returns PASSED
  without evaluation.
- **Empty sets never pass.** `evaluateGateReviews([]).allPassed === false` — absence of gates is
  absence of assurance. Same for an evaluation with zero declared mission gates.
- **Evidence resolution is usable-or-not** (composes with `missionEvidenceIsUsable`): a submission
  evidence ref resolves only against a ledger record with the same id AND the same kind, active
  lifecycle, complete integrity/provenance fields, same tenant. Revoked/superseded, malformed, or
  cross-tenant evidence never resolves.
- **Windows are enforced, not advisory:** `notBefore`/`expiresAt` on the gate; `submittedAt` in
  the future is blocked; timestamps must parse (`isContractTimestamp` from the mission contract).
- **Waivers are never a bypass.** `GateWaiver` is Zod-strict, evidence-bearing by construction
  (min 1 evidence ref, resolved against the ledger), authority-attributed (`grantedBy` +
  `authorityRef`), and time-bounded (`grantedAt`/`expiresAt` enforced at evaluation). They apply
  ONLY to security gates; a misplaced, mismatched, future-granted, expired, or evidence-less
  waiver leaves the gate BLOCKED with the reason named.
- **Strict shapes:** `z.strictObject` throughout (`gateDeclarationSchema`, `gateSubmissionSchema`,
  `gateWaiverSchema`, `gateEvidenceRefSchema`) so undeclared semantics cannot leak in; bounded
  collections (`GATE_LIMITS`); distinct `requiredEvidenceKinds` / `evidenceRefs`.
- **Mission composition (read-only):** `evaluateMissionGates(core, reviews, ctx)` binds reviews to
  the mission's declared admission gates — undeclared gateIds, kind mismatches, duplicates, and
  missing submissions are all BLOCKED/reported — and the CLOSURE gate composes with
  `missionEvidenceCovers` so EVIDENCE before SUCCESS holds at closure (gate-local coverage alone
  cannot close a mission). `GATE_KINDS` is compile-typed `satisfies readonly MissionGateKind[]`
  so the taxonomy cannot fork from `mission-contract.ts`.

## Security Validation

- Fail-closed by construction: every deny path returns BLOCKED with reasons; nothing throws on
  hostile input and nothing "repairs" it.
- No secrets: no credential material in any type, schema, fixture, or reason string.
- Tenant containment: gate tenant vs evaluation tenant is compared; cross-tenant gates,
  submissions, evidence, and waiver evidence are all blocked (mandatory §31 isolation check).
- Expiry honored: expired gates, expired waivers, and future-dated submissions cannot pass
  (mandatory §31 expired-access check).
- Strict TypeScript: zero `any`, zero `z.any()`, zero `as unknown`, zero type assertions on
  failure paths; Zod strict objects at every parse boundary.
- Domain neutrality (J-037): gate/evidence/waiver vocabulary only; no domain words in code.
- No git commands, no database, no network service, no package.json changes, no new dependencies
  (zod already a repo dependency), no existing test weakened or touched.

## Known Risks

- The PASSED brand is a compile-time + module-privacy guarantee; a runtime forger in the same
  process could still fabricate an object with a matching symbol via `Object.getOwnPropertySymbol`
  tricks — mitigated by the fact that verdicts are consumed only by their `outcome` discriminant
  and by the platform-level gates (the kernel registry at the write API remains the enforcement
  point per V1CAP-002).
- Waivers currently require at least one usable evidence ref but do not constrain its kind;
  tightening waiver evidence to a dedicated kind (e.g. `authority_attestation` only) is a
  one-line schema change left for the gate-consumer phase to decide.
