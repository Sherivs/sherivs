# H3-018 — Memory Scoping Enforcer (B-018 / J-029) — §42 Report

Role: Memory Scoping Enforcer (J-029), Squad B. Mission: session/mission/long-term
memory-scope enforcement with NO silent scope expansion.

## Implemented

`frontend/src/lib/context/memory-scope-enforcement.ts` — a pure, Zod-validated,
fail-closed contract:

- **Declared scopes across three retention tiers** (`session` | `mission` |
  `long_term`) with structural tier-binding invariants: session scopes MUST
  carry a session binding with an expiry, mission scopes MUST carry a mission
  reference, long-term scopes MUST carry neither (Zod `superRefine`).
- **Deny-by-default gates** (`enforceMemoryScopeAccess`) in fixed order:
  invalid clock → malformed request → undeclared scope → cross-tenant →
  principal not in scope → action not declared → session expiry →
  domain outside scope → sensitivity above ceiling. Empty principals, empty
  domains, and empty actions grant NOTHING.
- **NO SILENT SCOPE EXPANSION**: out-of-scope access is DENIED with a typed
  reason (`domain_outside_scope`, `sensitivity_above_ceiling`, …) — never
  clamped, never coerced, never partially granted. A failed attempt never
  mutates the scope (revision and ledger unchanged).
- **Expansion as an explicit, audited, typed act**
  (`applyMemoryScopeExpansion`): the ONLY widening path is a discriminated-union
  act (`add_domains` | `add_principals` | `raise_sensitivity_ceiling` |
  `extend_session`) carrying full provenance (declaredBy, authorityRef, reason,
  decidedAt). Acts must actually expand (no-op/narrowing acts are rejected),
  `extend_session` applies only to session-tier scopes, the scope revision
  bumps by exactly 1, and the act lands in an append-only per-scope expansion
  ledger. Failed acts mutate nothing.
- **Full audit**: every access decision (allowed AND every denial) appends a
  `MemoryScopeDecisionRecord` (§12 provenance, §29 observability) stamped with
  the injected audit instant — no wall-clock sampling anywhere.
- **Composition (read-only)**: sensitivity vocabulary is REUSED from
  `frontend/src/lib/context-assembly.ts` (`ContextSensitivity`) — never
  redefined (bidirectional type equivalence asserted in tests). Design
  composes with `agent-memory.ts` and `memory/memory-store.ts` invariants
  (declared-scope writes, audited access, no agent-owned memory) without
  modifying them.

## Architecture Impact

Additive contract module in `frontend/src/lib/context/` (own file, no edits to
existing modules). Follows Domain → Application layering: pure data + pure
functions, no I/O, no vendor, no persistence; server-side authorization remains
mandatory (this is one enforcement layer, never the only one — Constitution
§17, §34). Neutral vocabulary throughout (J-037). Supports Constitution §6
(agents cannot silently expand memory access) and §8 (self-improvement ≠
permission expansion).

## Security Validation

- Fail-closed everywhere: unknown/undeclared scope, cross-tenant principal,
  expired session, empty grants — all deny with typed reasons.
- No silent expansion: enforcement is an upper bound, never a normalizer;
  widening requires an explicit typed act with provenance, recorded in an
  append-only audit ledger (Constitution §6/§8/§12).
- No secrets printed/logged/written; no database or network access; no
  destructive operations; time injected (deterministic, auditable).
- UI-independent contract — backend enforcement semantics only (§34).

## Known Risks

- The contract is a pure in-memory layer; persistence-side enforcement
  (cg_memory_* RLS, deny-by-default) remains the database tier's
  responsibility (authored migrations, not applied — coordinator owns apply).
- Shrinking/revocation of a declared scope is deliberately NOT offered in this
  V1 module; it must be a separately governed operation (recorded as remaining
  work, not silently absent).
- Scope expansion acts are validated for internal consistency (actually
  expands, tier-correct, provenance complete) but are not cross-checked
  against an external approval workflow in this module; callers must resolve
  authorityRef against the authorization layer.
