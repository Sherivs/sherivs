## Implemented

`tests/unit/h3-092-paystack-failure-semantics.test.ts` — 26 offline tests pinning the REAL failure paths of the Paystack adapter stack (inspected read-only before authoring; no invented APIs):

1. **Declared failure-policy wiring (J-045).** The BLK-4 contract adapter carries `PAYSTACK_FAILURE_POLICY` (provider `paystack`, 5s timeout, 1 attempt, degraded 3/60s, breaker 5/30s) and starts healthy/closed/unproven; injected policies pass through by identity; the TEST-MODE client declares its own budgets (10s timeout, 2 attempts); misconfiguration fails fast (`TypeError`) — policy can never silently weaken itself (degraded ≤ breaker invariant, positive/integer budgets, backoff cap ≥ base). Refund capability stays BLK-4 blocked; `paystackRefundUnsupported()` denies with `unsupported`.
2. **Degraded mode.** Arms exactly at the declared 3-consecutive-failure threshold with a `mode_change` event on the event sink (never silent); time-bounded (expired after the 60s window: `degradedActive` stays true, `mode` returns healthy); cleared by the first success (degraded→healthy event); re-armed as a fresh announced episode by further failures.
3. **Circuit breaker.** Opens at the declared 5-failure threshold; external calls denied with `breaker_open`, `attempts: 0` and "without provider contact"; exactly one half-open probe admitted after the 30s reset window (success closes, failure re-opens with a fresh next-probe time); concurrent half-open probes denied while the probe is in flight.
4. **Local containment never gates.** `verifySignature` / `parseWebhook` / `createIntent` keep working while the provider is degraded AND while the breaker is open (isolated) — local verification survives provider distrust; local successes never close an open breaker (only the half-open probe does). Every webhook failure (unsigned, forged, garbage body, unknown event, non-integer amount, invalid reference) is a structured result, never a throw into the host loop.
5. **Trust ledger (E-060).** Recommendations start `unproven` (reason cites "never automatically trusted"); breaker-level failures flip the recommendation to `untrusted`; one success does NOT absorb failure-rate evidence (5/6 ≥ 0.5 stays `untrusted`); no implicit trust decision is ever recorded (`currentTrustVerdict()` stays `unproven`, `trustDecisions()` empty). Compile-time pin: the recommendation verdict space excludes `"trusted"`.
6. **TEST-MODE live-client failure semantics (fully offline).** Hung provider contained as `timeout` with the mutation attempted exactly once (replay protection — no transport retry) and audit evidence surviving (`totalTimeouts` recorded); transport rejection and HTTP 500 contained as `provider_error` carrying the provider's message but never key material; non-conforming 200 responses denied as `malformed_response`; idempotent verification retries within the declared 2-attempt budget with deterministic 250ms backoff (exact delay sequence `[10_000, 250, 10_000]` pinned); ownership re-checked against the canonical reference — amount mismatch, currency mismatch and malformed verify payloads all deny (`ownership_mismatch` / `malformed_response`); audit-before-execute holds under provider failure (audit precedes transport) and a throwing audit sink denies the mutation before any provider contact (`audit_failed`, zero transport calls); TEST-MODE breaker denies without provider contact, closes via a successful probe, re-opens via a failed probe.

**Method notes.** All provider I/O goes through injected transports; all time flows through injected clocks. Two deterministic clock shapes are used: a deferred manual clock (delays resolve only when the test fires them — used for timeout timing and breaker-reset windows) and a macrotask clock (virtual time advances instantly, delays settle on the next macrotask — used so fast-settling transports win the policy's `Promise.race` timeout race while retry loops still complete). No network, no database, no `vi.useFakeTimers`; runtime ~270ms.
