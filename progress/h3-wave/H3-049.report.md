# H3-049 — Health Map Engineer — §42 Report

Mission F-049: dependency health inventory contract feeding the existing `/health.json` contract, fail-closed on unknown/dead checks.

## Implemented

- `frontend/src/lib/observability/health-map.ts` — a declarative dependency health inventory:
  - Zod-validated (`zod` v4, already in the dependency tree — no new dependency) entry schema: neutral lowercase `name`, `criticalityTier` (`critical | major | minor`, exactly three tiers), `checkContractRef` (reference to the owning check contract), and per-entry provenance (`declaredBy` / `authority` / `declaredAt` ISO-8601 UTC — AGENTS §12). Strict objects: unknown keys are parse failures.
  - Inventory law: at least one entry (an empty map cannot claim healthy), duplicate names are a parse failure (no silent override); `parseDependencyHealthMap` for fail-closed external parsing.
  - `evaluateHealthMapPosture(inventory, rawResults)` — pure aggregation into `ok | degraded | failing` with typed findings (`observed | dead_check | unknown_check | invalid_result | duplicate_result`), fail-closed on:
    - **dead check**: declared but never observed → `failing` (silence is never health);
    - **unknown check**: observed but never declared → `failing` (undeclared signals are never absorbed);
    - **invalid result**: unnameable / malformed / out-of-contract status → `failing`;
    - **duplicate result**: repeated name → `failing` (ambiguous telemetry is never averaged away).
  - Tier escalation: a `degraded` result on a `critical`-tier dependency escalates the overall posture to `failing`; `failing` anywhere is `failing` overall.
  - Composition is READ-ONLY with `frontend/src/lib/observability/health.ts` (the `/health.json` contract): `buildMapHealthReport` consumes `buildHealthReport`, `normalizeCheckResult` and `aggregateStatus` via imports only; `health.ts` is untouched (no edits made).
- `tests/unit/h3-049-health-map.test.ts` — 24 offline tests (parsing law, aggregation law, fail-closed semantics, read-only composition with `./health` including throwing checks and unwired/undeclared checks).

## Architecture Impact

- None adverse. Adds an inventory plane over the existing execution plane (`./health`); the health endpoint contract is composed read-only and its shape is unchanged. The map posture is advisory-on-top and fail-closed-superseding: when it exceeds `report.status` in severity, the posture is authoritative (documented in-module). Ownership boundaries respected: single new module in `frontend/src/lib/observability/` (its own file, no root-level `.ts`, no `kernel/phase-contracts/` path — J-037 neutrality law observed).

## Known Risks

- The inventory is declarative config owned by callers; a mis-declared name (not matching what the executable check reports) will surface as dead + unknown checks simultaneously — this is fail-closed by design but could raise operator noise until the map is reconciled with actual wiring.
- Tier escalation policy (`degraded` on `critical` → overall `failing`) is a V1 policy default declared in-module; if operators disagree, it is a one-constant change (`CRITICAL_TIER`) pending an ADR.
