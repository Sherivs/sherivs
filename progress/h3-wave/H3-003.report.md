# H3-003 — Backup Manifest Engineer (§42 Report)

Mission: A-003 — typed backup-manifest schema (scope, checksums, instant, expiry, tenant coverage), consumable by A-001's offline rehearsal.

## Implemented

- `frontend/src/lib/reliability/backup-manifest.ts` — pure, Zod-validated contract for what a valid backup set is:
  - **Scope** (`BackupScopeSchema`): declared record families (`records | attachments | audit | configuration`) with non-negative record counts; at least one family required; count 0 is allowed as declared emptiness; duplicate families rejected.
  - **Checksums** (`ChecksumSchema`): algorithm allowlist (`sha256`/`sha512`), lowercase-hex digests with per-algorithm length enforcement (64/128) on every entry and on the manifest-level checksum; duplicate entry ids rejected; storage refs must be relative with no upward traversal.
  - **Instant + expiry** (`capturedAtMs`/`expiresAtMs`): expiry mandatory, must be strictly after the instant (`lifetime_inverted`); optional `maxRetentionMs` bound (`retention_window_exceeded`); clock is caller-injected (`nowMs`) — expired (`expired`) and not-yet-valid (`not_yet_valid`) manifests fail closed; without `nowMs` only shape/lifetime rules run and the caller cannot claim freshness.
  - **Tenant coverage** (`TenantCoverageSchema`): at least one tenant ref, duplicates rejected; `partial` flag distinguishes full vs subset coverage — no "unknown coverage" parses.
  - Typed issue codes (`BackupManifestIssueCode`) with all issues accumulated, never truncated to the first; versioned (`BACKUP_MANIFEST_SCHEMA_VERSION = 1`) with a dedicated `schema_version_unsupported` code; untrusted garbage never throws.
  - Pure queries: `backupManifestStatus`, `coversTenant`, `declaredRecordCount`, `isWellFormedChecksum` (format validation only — integrity verification stays at the storage layer).

## Security Validation

- Fail closed: expired, not-yet-valid, version-unsupported, malformed, and zero-coverage manifests are all rejected with typed reasons; nothing degrades silently.
- Multi-tenancy law honored: tenant coverage is mandatory and explicit; coverage is descriptive and confers no access rights (stated in module doc and `coversTenant` doc).
- No I/O, no vendors, no secrets handled or logged; checksum validation is format-only, so no integrity claim is faked.
- Storage-ref traversal (`..`, absolute paths) rejected at the contract layer.
- Domain neutrality (J-037): only neutral vocabulary (`records`, `attachments`, `audit`, `configuration`) in `frontend/src/lib/reliability/`.

## Known Risks

- The manifest checksum field is a provenance hook; the module validates its format but nothing yet recomputes it over serialized bytes (deliberately out of scope for a pure contract; A-001's rehearsal and the drill tooling are the natural consumers).
- Default validation without `nowMs` cannot judge freshness by design; callers must inject time to get a usability verdict. Documented in the options contract.
- `BACKUP_ENTRY_KINDS` is a closed allowlist; new content kinds require a schema-version bump (intended friction).
