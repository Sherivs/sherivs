## Implemented

`frontend/src/lib/universal-runtime-fabric/contracts.ts` — a pure, Zod-typed,
fail-closed, domain-neutral CONTRACT module encoding the phase-40 substrate
surface's neutral runtime-registration semantics. Under RULING-1 (runtimes are
data to the platform, never platform content), a runtime joins CoreGrid as a
declaration over a stable contract; installing/suspending/resuming/retiring it
is a data operation that never rewrites the kernel.

Surface:

- **Hard ceilings** — every declaration array and resource field is bounded
  (`MAX_ONT_ENTITY_TYPES`, `MAX_CAPABILITY_REFS`, `MAX_CONCURRENT_TASKS`, …);
  no unbounded runtime declarations.
- **`runtimeRefSchema`** — canonical kernel manifest id (validated via a
  read-only import of `kernel/domain-manifest.isValidManifestId`) pinned to
  the `runtime:` namespace.
- **`runtimeDescriptorSchema`** — ontology (entity/relationship type names
  with duplicate and endpoint-resolution checks; universal pseudo-types
  accepted), consumed canonical `capabilityRefs`, mandatory `policyRefs`
  (a runtime with no declared policies cannot be registered), interfaces
  (kernel `api|event|ui` vocabulary), explicit `isolation`
  (`tenantScoped: z.literal(true)` — only `true` parses; egress and state
  mode must be declared, never defaulted), `resourceCeiling`.
- **`registrationProvenanceSchema`** (AGENTS §12) — requesting actor/role
  reference (never a credential), governing authority, strict UTC RFC-3339
  instant, non-empty justification; incomplete provenance fails closed.
- **`runtimeRegistrationRequestSchema`** — discriminated union on intent
  (`install | suspend | resume | retire`); strict shape (unknown keys and
  storage-declaration keys are parse failures, never ignored).
- **`registrationContextSchema`** — server-resolved context only
  (§26/§27): the caller never supplies tenant or registry view; the decision
  trusts only the context's `resolvedTenantRef`, `actorRef`, canonical
  capability vocabulary, and registry snapshot.
- **`decideRuntimeRegistration(request, context)`** — the fail-closed
  ALLOW/DENY decision (§16): unparseable request/context denies with typed
  reasons (`DENIAL_REASONS`) plus bounded detail; duplicate registration and
  cross-tenant canonical-ref collision deny (`duplicate_registration`,
  `tenant_mismatch`); unknown refs deny; foreign-tenant lifecycle operations
  deny (§31: tenant A cannot act on tenant B); retired runtimes are terminal
  (`retired_runtime`); suspend requires `active`, resume requires
  `suspended` (suspended access fails closed); every accepted move is
  re-validated against the kernel transition law imported read-only from
  `kernel/runtime-registry.ts`; install lands in `proposed` ONLY — no path
  in the module self-activates a runtime (§21).
- **`runtimeHealthSignalSchema` + `unknownRuntimeHealthSignal`** — unproven
  health is `unknown`, never optimistic `healthy`.
- Parsers (`parseRuntimeDescriptor`, `parseRuntimeRegistrationRequest`,
  `parseRegistrationContext`, `parseRuntimeRegistrationDecision`,
  `parseRuntimeHealthSignal`) return typed `{ ok: true, value } |
  { ok: false, issues }` — never throw, never guess.

Boundary: no I/O, no persistence, no vendor imports, no secrets, no timers
(all instants flow from the caller); volumetric quota enforcement and the
concurrency lease plane are deliberately NOT re-declared here (owned by the
reliability contracts) — this module bounds only what a runtime may DECLARE.
Composition is read-only over platform primitives
(`kernel/domain-manifest.ts`, `kernel/runtime-registry.ts`); no sibling H3
module is imported.
