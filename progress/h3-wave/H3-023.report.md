## Implemented

`frontend/src/lib/adapters/failure-semantics.ts` — the external-adapter failure-semantics contract layered on the existing `AdapterFailurePolicy` (`frontend/src/lib/adapters/failure-policy.ts`, READ-ONLY import — composition, never modification). What the layer adds on top of the policy engine:

1. **Fail-closed per-provider admission gates**, cheapest first, all BEFORE any provider contact: `unknown_provider` (an undeclared provider admits nothing — no permissive default), `invalid_call_spec` (blank operation, non-function call, attempts override above the declared cap — attempts can be tightened, never expanded), `trust_gate` (E-060), `degraded_denied`.
2. **Bounded, provenanced declarations**: `parseProviderFailureProfiles` (Zod, `strictObject`, no `z.any`) validates every provider failure profile — hard ceilings `MAX_PROVIDER_TIMEOUT_MS` (60s), `MAX_ATTEMPTS_PER_CALL` (8), `MAX_BACKOFF_MS` (60s), `MAX_DEGRADED_WINDOW_MS`/`MAX_BREAKER_RESET_MS` (5 min), `MAX_BREAKER_THRESHOLD` (100) — plus cross-field invariants (`backoffCapMs ≥ backoffBaseMs`; `degradedAfterFailures ≤ breakerFailureThreshold`) as structured parse failures, and mandatory provenance (`declaredBy`/`authority`/`declaredAt`, AGENTS §12). Misconfiguration is a parse failure, never a construction-time throw.
3. **Strict provider isolation**: each declared provider owns a private policy instance (ledger, breaker, degraded episode, trust log); one provider's failure history can never contaminate another's.
4. **Degraded-mode behavior declared per provider** (`whileDegraded: "admit" | "deny"`): `"deny"` fails closed during an episode without provider contact; recovery is unaffected because an isolated adapter (breaker open/half-open) is never in the degraded mode, so the policy's half-open probe always reaches the policy; the episode expires by its window or clears on first success.
5. **Per-provider trust decisions (E-060)**: the gate consults an EFFECTIVE verdict — the last explicit decision when one exists, otherwise the policy's recommendation. The recommendation space can never contain `"trusted"`, so without an explicit decision a provider is admitted only while `"unproven"`; a failure history past the trust floor (consecutive-threshold or failure-rate evidence) denies all calls at the gate until a governed `recordTrustDecision` (non-empty `decidedBy`, provenanced basis) re-admits it. Recommendation transitions into/out of distrust are announced exactly once (`trust_recommendation` events); malformed decisions are rejected and recorded (`trust_decision_rejected`).
6. **Containment all the way down**: `run`/`containSync` return structured results and never throw; even a defect inside this layer is contained as `internal_defect`. `containSync` never trust-gates (local verification keeps working while a provider is distrusted), per the base law.
7. **Observability**: every gate denial, policy event, and trust event lands in an immutable in-memory audit trail; an injectable sink receives both sources, and a throwing sink can never break containment.

Pure in-process contract: no I/O, no persistence, no vendors, no secrets, no implicit timers — all time flows from the injected `AdapterClock`.

## Security Validation

- **Fail closed:** undeclared providers admit nowhere; invalid specs admit nowhere; distrusted providers deny all calls without contact; degraded deny episodes admit nothing; malformed trust decisions are rejected and logged. No permissive default exists in any path.
- **E-060 invariant enforced and tested:** the automatic verdict space is only `"unproven" | "untrusted"`; `"trusted"` is reachable exclusively through an explicit decision carrying `decidedBy`, reason, and the failure-history basis (provenance, §12); the policy's immutable decision log is the audit record.
- **No secrets:** no credential material in any type, schema, fixture, event, or reason string; nothing is logged or printed by the module.
- **No bypass:** the gates run before the policy boundary; the policy's own timeout/breaker/degraded enforcement remains as defense in depth (e.g. a trusted-but-breaker-open provider is still denied by the policy, without contact).

## Known Risks

- The trust gate denies whenever the policy's recommendation is `"untrusted"` (consecutive failures ≥ breaker threshold, or rate evidence). A provider that reaches its breaker threshold therefore also hits the trust gate and needs an explicit decision to re-admit — conservative by design (E-060); operators re-admit via `recordTrustDecision`.
- Audit trail is in-memory (per-process); durable audit persistence is out of V1 scope for this contract and remains with the platform's audit substrate.
- The `internal_defect` containment arm is a belt-and-suspenders path that tests exercise indirectly only (a policy-internal defect is not injectable from the public surface).
