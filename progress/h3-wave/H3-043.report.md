## Security Validation

- **Fail-closed gate:** missing key, live key, and any other credential class all exit 2
  BEFORE any network contact; tests assert no round artifact is written on any blocked
  path and the block message is constant-shaped (no value echo).
- **Live-key refusal by design:** dual enforcement — runner gate (`sk_live_` blocks like
  missing) and the governed surface's independent `validateTestModeKey` (`non_test_key`),
  proven offline via the rehearsal vectors.
- **Secret hygiene:** the key VALUE is never printed, logged, or written; sentinel-value
  probes assert stdout, stderr, record JSON, and rehearsal log are value-free on both
  the rehearsal path and the blocked path. Deny reasons are secret-free (inherited from
  the governed module).
- **§36 controls exercised by the round design:** audit-before-execute, idempotency
  (derived key registered provider-side), ownership validation (owned re-check +
  negative mismatch probe), replay protection (same-reference dedupe), never trusting
  client payment state (amounts come from the server-side plan).
- **No destructive/privileged action:** no database contact, no migration, no policy
  change, no charge ever completed.
