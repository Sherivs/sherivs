## Known Risks / FINDINGS (module NOT modified; each finding is a test in the suite asserting the precise observed behavior)

- **FINDING H3-075/F-1 (HIGH) — writeback-bypass via forged approval:
  `decideSimulatedWriteback` never re-validates `options.approval`.**
  The module exports `WritebackApprovalSchema` but the decision gate runs
  it only on the proposal, never on the approval. A runtime-forged
  approval object missing `expiresAtMs` and `revoked` reaches `ALLOW`:
  `undefined <= nowMs` is false, so the expiry gate is skipped and
  `undefined` revocation is falsy. Repro: `tests/unit/h3-075-...test.ts`,
  "FINDING H3-075/F-1". Root fix for the module owner: `safeParse`
  `options.approval` with `WritebackApprovalSchema` and fail closed
  (`DENY invalid_input`-class reason) on mismatch.
- **FINDING H3-075/F-2 (HIGH) — denial-by-exception: a forged approval
  missing `subjectRefs` (with a matching tenant) crashes the gate with
  `TypeError` instead of producing a typed denial.** Any caller wiring
  untrusted approval JSON into the gate turns a parse failure into a
  500-class crash instead of `DENY`. Same root cause as F-1
  (approval never schema-checked).
- **FINDING H3-075/F-3 (HIGH) — a `NaN` injected clock evades every
  expiry check in the module.** `x <= NaN` is false, so:
  an expired approval is granted `ALLOW` at the writeback bridge; an
  expired outcome passes `validateSimulationRunBundle` as `ok: true`; an
  expired outcome is reported `usable: true` by
  `usabilityForDecisionSupport`. The clock is caller-injected by design,
  but degenerate clock values are never validated — hardening candidate:
  reject non-finite/non-integer `nowMs` fail-closed at all three entry
  points.
- **FINDING H3-075/F-4 (MEDIUM) — the writeback bridge never re-checks
  the freshness/validity of the embedded outcome.** A proposal whose
  outcome is expired (`validUntilMs < nowMs`) or has inverted validity
  (`validUntilMs <= generatedAtMs`) is granted `ALLOW` with a valid
  approval/policy/audit. Expired derived intelligence can therefore be
  approved toward a canonical surface, contradicting §31 ("expired access
  fails") and the module header's own claim that the bridge implements
  §9/§16/§21 fail-closed. Note: the per-item schema cannot catch inverted
  validity (it is a cross-field invariant enforced only in
  `crossFieldIssues`, which the bridge does not run).
- **FINDING H3-075/F-5 (MEDIUM) — timestamps are never checked against
  the injected clock.** An outcome with `generatedAtMs`/`validUntilMs`
  (and `provenance.recordedAtMs`) forged days or years into the future
  passes validation and remains "fresh" until the forged horizon —
  expiry is indefinitely deferrable by whoever controls the artifact.
  Hardening candidate: `generatedAtMs <= nowMs` (and provenance
  sanity) invariant in `crossFieldIssues` / the bridge.
- **FINDING H3-075/F-6 (MEDIUM) — `usabilityForDecisionSupport`
  performs no outcome↔bundle binding.** It consults only
  `bundle.status`, `outcome.validUntilMs` and `outcome.confidence`: a
  laundered outcome from another run, another tenant and outside the
  subject scope is marked `usable: true` against a legitimate bundle.
  Hardening candidate: assert `outcome.runId === bundle.run.runId`,
  `outcome.tenantRef === bundle.scenario.tenantRef`, and subject-scope
  membership inside the function (or require callers to pass
  `bundle.outcomes[i]` by construction and document it).
- **FINDING H3-075/F-7 (MEDIUM) — unbounded cardinality on outcomes,
  subjectRefs and assumptions.** `parameters` is capped (`max(64)`), but
  `outcomes` (bundle), `subjectRefs` (scenario/outcome/proposal) and
  `assumptions` have no maxima: a 1500-outcome flood bundle and a
  10000-subject scenario both parse and validate. The flood surface is a
  CPU/memory exhaustion vector for any server path that validates
  untrusted bundles. Hardening candidate: declared maxima consistent with
  the `maxRuns`/bounded-run philosophy (e.g. outcomes ≤ scenario-declared
  bound).
- **FINDING H3-075/F-8 (LOW) — asymmetric trimming: the audit-destination
  gate checks only presence.** `auditDestinationRef: "   "` passes the
  audit gate (`ALLOW`) while an identical `policyRef: "   "` is trimmed
  and denied (`no_policy`). A whitespace-only "audit destination" is an
  unauditable write grant under the module's own §29 rule.
- **FINDING H3-075/F-9 (LOW) — the absolute horizon cap is opt-in.**
  Without caller-supplied `maxHorizonSteps`, a run with
  `horizonSteps: Number.MAX_SAFE_INTEGER` (scenario bound attacker-matched)
  validates `ok: true`, despite the module header declaring "an unbounded
  simulation is invalid". The runaway guard is documented as an option;
  server callers MUST supply it. Retained as a documented risk with the
  containment probe in-suite.
- **Known risk (non-finding, noted): `SubjectRefSchema`'s refine blocks
  only leading-`/` paths.** A relative-path-shaped ref (`./relative/ref`)
  parses at shape and is still contained at the approval gate
  (`approval_mismatch_subject`), but the schema's "not a path" intent is
  only partially enforced. Vocabulary-level nit for the module owner.
