## Implemented

`frontend/src/lib/reliability/recovery-targets.ts` — a pure, Zod-validated contract module binding record families to recovery commitments:

- **Declaration schema** (`recoveryTargetDeclarationSchema`): one record family ↔ complete commitment — `rtoMinutes` + `rpoMinutes` (positive whole minutes under hard ceilings `RTO_CEILING_MINUTES` / `RPO_CEILING_MINUTES` = 1,440) + mandatory provenance (`declaredBy`, `authority`, ISO-8601 `declaredAt` — AGENTS §12). Strict shape (`z.strictObject`); no partial commitments, no anonymous commitments, no unknown keys.
- **Registry schema** (`recoveryTargetRegistrySchema`) with an optional tighter `recoveryEnvelope` (can only narrow the global ceilings, never widen — enforced structurally).
- **Fail-closed parsing** (`parseRecoveryTargets`): untrusted `unknown` input in; on any violation returns typed `ok: false` with structured issues and a failure reason (`invalid_shape` | `cross_record_invariant`). Cross-record invariants: duplicate record families rejected (one family, one binding); declarations must fit the registry envelope. A failed parse never yields a partial registry.
- **Fail-closed resolution** (`resolveRecoveryTarget`): an undeclared family resolves to `status: "undeclared"` with reason `no_declaration_for_family` and an explicit detail (`FAIL_CLOSED_UNDECLARED_DETAIL`) stating that no recovery commitment is assumed. No permissive default is ever fabricated.
- **Named-gap coverage** (`coverageForFamilies`, `undeclaredFamilies`, `coverageGaps`): explicit per-family coverage view; `coverageGaps` fails closed with a structured `detail` whenever any required family is undeclared — gaps are named, never silent.
- **Bounds-default clarity** (`effectiveEnvelope`): falls back to the global ceilings when no envelope is declared; this is a bounds default (what declarations must fit), never a commitment default (what families are promised).

## Security Validation

- **Fail-closed defaults (campaign law 6 analogue):** undeclared family ⇒ `undeclared` posture, never an inherited permissive target — asserted explicitly in tests.
- **No partial success:** any schema/cross-record violation returns `ok: false`; no partial registry ever escapes a failed parse — asserted.
- **Strict typing:** no `any`, no `z.any()`, no type assertions on failure paths; `z.strictObject` throughout (no implicit key tolerance).
- **Provenance mandatory:** declarations without `declaredBy`/`authority`/`declaredAt` are rejected (AGENTS §12).
- **Bounded commitments:** hard minute ceilings; no unbounded recovery promises.
- **No secrets:** the module and tests handle no credentials; `declaredBy`/`authority` are role/authority references, not secrets.
- **Offline:** the test run performs zero network/database access.

## Known Risks

- The RTO/RPO ceiling of 1,440 minutes is a module-level wave default; if the operator later ratifies different ceilings, the constants (or a per-registry envelope) are the only change point — no downstream schema edits needed.
- Resolution functions assume an already-parsed registry (documented in the module header); a hand-constructed registry object could bypass parse-time invariants. Mitigation is convention (parse at the boundary), consistent with how other contract modules in the repo treat parsed inputs.
- Registry declaration count is bounded at 1,024; a tenant needing more families would require raising that bound (review-gated change).
