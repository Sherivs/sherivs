## Implemented

`frontend/src/lib/audit/query-surface.contract.ts` — a pure, contract-only Zod module governing every audit READ request:

- **Tenant-bound**: exactly one `tenantId` per envelope; the schema is a strict object with no tenant-listing, wildcard, or cross-tenant filter field anywhere — cross-tenant queries are structurally unrepresentable (unknown keys are parse failures).
- **Time-bounded**: `timeWindow` is mandatory, ordered (`toIso` strictly after `fromIso`), and capped at `MAX_AUDIT_WINDOW_MS` (7 days); optional injected-clock anchor refuses windows ending more than `MAX_FUTURE_SKEW_MS` (60s) in the future.
- **Actor-scoped**: exactly one concrete `actorRef` per envelope; "all actors" is not a representable scope.
- **Structurally unbounded-proof**: `pagination.limit` mandatory, 1..`MAX_PAGE_LIMIT` (200); zero/absent/over-ceiling limits refuse; filters (`action`, `tableName`, `recordId`) are optional and narrowing-only.
- **Purpose-bound**: non-blank `purpose` (min 8 chars) required (AGENTS §16 purpose limitation).
- **Read-only results**: `parseAuditPage` validates, refuses any record whose `tenantId` differs from the envelope tenant (typed `cross_tenant_record_refused`), and returns a deep-frozen `FrozenAuditPage` (`freezeAuditPage`).
- **No DB binding**: declares the `AuditReadAdapter` interface for the store layer behind RLS; the module never imports, constructs, or binds a client (AGENTS §17/§28 — RLS stays the real boundary; the tenant-coherence check is defense in depth).
- **Read-only composition**: composes with the existing write-side helper `frontend/src/lib/audit.ts` via an erased type-only import of `AuditAction` (shared vocabulary, no runtime/Supabase coupling).

## Security Validation

- Unbounded queries fail closed: missing window/actor/limit/tenant/purpose, over-ceiling window/limit — all parse refusals, never permissive defaults.
- Cross-tenant requests are structurally unrepresentable (strict objects, single-tenant/single-actor fields) and pages leaking foreign-tenant records are refused with a typed refusal code even against a misbehaving adapter.
- Result surfaces are deep-frozen read-only views.
- No secrets handled, printed, or logged; module contains no credential paths and no network/DB access.
- No existing tests weakened; no shared files touched; only the owned test executed.

## Known Risks

- `MAX_AUDIT_WINDOW_MS` (7 days) and `MAX_PAGE_LIMIT` (200) are contract constants chosen by this mission; coordinators may want them ratified in an SLO/ops card (F-051) if audit retention windows differ.
- The tenant-coherence check on pages is defense in depth only — actual isolation relies on RLS policies at the DB layer (per §17); the contract cannot compensate for a store adapter that bypasses RLS.
- The future-window check requires callers to pass `options.nowMs`; without it, only relative window ordering/bounds are enforced.
