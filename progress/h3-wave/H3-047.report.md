## Implemented

`frontend/src/lib/observability/trace-context.ts` — the trace_id/correlation_id propagation contract:

- **Typed context**: `TraceContext` (frozen plain data: `trace_id`, `correlation_id`, `created_at_ms`, bounded `attributes`) with Zod contracts (`traceIdSchema`, `correlationIdSchema`, `traceAttributesSchema`, `traceContextSchema`).
- **Generation**: 128-bit ids from `crypto.getRandomValues` where the platform provides it; documented counter+seeded-FNV-1a fallback for exotic runtimes (uniqueness primitive only — carries no trace data). Time enters only via the kernel time authority (J-023) or an injected `now`.
- **Propagation across async boundaries by explicit parameter passing ONLY**: `runWithTraceContext(context, fn)` hands the context as a parameter; `propagateToChild` (trace continues, correlation refreshed per hop, attributes compose parent→child); `injectTraceContext`/`extractTraceContext` for wire/queue/header carriers; `continueTraceContext` for boundary merge (incoming trace wins; untrusted input never throws, never fabricates ids). No ambient store, no global slot, no async-context magic.
- **Redaction-safe serialization**: `serializeTraceContextFields`/`serializeTraceContext` emit a fixed whitelist; sensitive-keyed attributes are redacted via the shared structured-log redaction (`isSensitiveKey`, `redactValue`, `REDACTED`), and credential-shaped VALUES (key prefixes, Bearer/Basic, PEM headers, token/JWT shape, long hex/base64) are redacted via `isCredentialShapedValue` — over-redact, never leak (§29/§30).
- **Composition (read-only)**: imports only `structured-log.ts` (redaction primitives + `StructuredLogEntry`/`LogLevel` types) and the kernel time authority; `traceLogFields`/`traceLogEntry` produce house-shape entries consumable by `logStructured`/`formatLogLine` and the substrate-telemetry buffering pattern. Neither existing module was modified.

## Known Risks

- `isCredentialShapedValue` is a pattern list, not a semantic guarantee: a secret stored under an innocuous, non-credential-shaped value in an innocuously named attribute could pass. Mitigation is layering (sensitive-key redaction + Zod bounds + fixed whitelist); residual risk documented per §29's over-redact guidance.
- The no-WebCrypto fallback id path cannot be exercised on this runtime (Node exposes `globalThis.crypto`); it is covered by the schema-valid assertion branch only.
- 32-char hex trace ids are deliberately W3C-shaped; they match the long-hex credential pattern, so the whitelist (not value screening) is what guarantees ids serialize verbatim — asserted by test.
