## Implemented

Authored the Zod-typed, fail-closed, domain-neutral contract surface for the phase-47 substrate (governed improvement loop), per `architecture/phase-47-autonomous-engineering-self-improvement-engine.md` and the phase-completion-status row 47 posture (`ARCHITECTURE_DEFINED`; contract-definition evidence only — no runtime/deployment claims). The module encodes AGENTS §8 (self-improvement ≠ permission expansion) STRUCTURALLY, not just in prose:

- **Protected change classes** (`security_boundary`, `authorization_model`, `identity_system`, `data_access`, `production_behavior`) — the five §8 classes as an enum with a fixed surface→review-kind mapping (`REVIEW_KIND_BY_SURFACE`).
- **Unrepresentable unreviewed protected change**: `improvementProposalSchema.superRefine` rejects any proposal declaring a protected surface without a `review` block whose `humanApprovalRequired` is the schema literal `true` and which names ≥1 required review kind; conversely, a review block on a routine proposal is rejected. The schema cannot express a protected-class change that skips human review and validation.
- **No machine ratification**: `ratificationSchema.ratifierKind` is the literal `"human"` — an agent ratifying its own work cannot even be parsed.
- **No self-approval (AGENTS §21)**: `decideRatification` fail-closes with `self_approval_forbidden` when the ratifier equals the proposal author, and binds a ratification to exactly one proposal.
- **No deploy/no ratify staging**: `stagingRecordSchema` carries `deploys: z.literal(false)` and `ratifies: z.literal(false)`; the proposal status enum (`draft`/`submitted`) contains no approved/ratified/deployed state, so approval outcomes are unexpressible on the proposal surface.
- **Same verification chain as any human change**: `verificationRunSchema` fail-closes (`passed` requires every gate `passed`; gates are mandatory and evidence-referenced); `gateStaging` blocks staging on `verification_run_missing` / `verification_run_mismatch` / `verification_not_passed`.
- **Evidence-based loop input (AGENTS §9)**: signals require ≥1 evidence item; proposals cite ≥1 observed signal, a named change AND a named rollback plan; regressions cannot carry `info` severity.
- **Pure decision helpers**: `classifyChangeReview` (§8 classification with unioned required review kinds; routine changes still route through the chain), `decideRatification`, `gateStaging`, `summarizeLoop` (unverified staging is a defect, never a pass).
- **Fail-closed batch parsing**: `parseImprovementProposals` with typed `invalid_shape` / `cross_record_invariant` (duplicate id) results; no partial sets.
- **Bounded inputs**: hard ceilings on statements (2,000 chars), evidence (64), signal refs (64), affected surfaces (16), gates (64), batch size (512).
- Boundary/law constants (`SELF_IMPROVEMENT_BOUNDARY`, `SELF_IMPROVEMENT_LAW`) for downstream citation.

Composition posture: pure contract module — no I/O, no persistence, no wall-clock reads, no vendor imports (only `zod`), no sibling H3 imports, platform primitives consulted read-only (`kernel/phase-contracts/phase-47-self-improvement.ts` boundary and `requiresApprovalFor` reflected as constants/literals).

## Security Validation

- Fail-closed defaults throughout: every gate defaults to refusal; `ok: true` is earned only by complete, matching, passing evidence.
- §8 encoded structurally: an unreviewed protected-class proposal is unrepresentable; machine ratification is unparseable; staging cannot express deploy/ratify intent; no self-approval path exists.
- No secrets: the module and tests contain no credential material; subject/provenance fields are role/principal references, never tokens.
- Neutral vocabulary (J-037): verified by the repository neutrality guard (PASS); education-domain tokens absent.
- No authorization decisions are made by this module: it validates structure and routes to human review; enforcement remains with phases 08/09/42 surfaces.

## Known Risks

- The module is contract-definition evidence only (matches phase 47's `ARCHITECTURE_DEFINED` posture): no runtime consumer, persistence layer, or live loop exists yet; wiring is a later bounded mission.
- `classifyChangeReview` derives review kinds from declared surfaces only; a proposal that under-declares `affectedSurfaces` would classify as routine. Mitigation for V1: reviewers cite the declaration; a future verifier mission (phase-47 verification suite) can add adversarial under-declaration checks.
- Ratification independence is enforced against the proposal author only; a full independence graph (e.g. shared-agent rings) belongs to the assurance surface, not this contract module.
