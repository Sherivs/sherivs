   conserve against flat totals with null refs under `UNASSIGNED_REF_KEY`.

## FINDINGS (read-only observations; metering modules NOT modified)

1. **F-093-1 (low): shared mutable zero-usage object.** `evaluateTenantQuota`
   returns the module-level `ZERO_USAGE` (a non-frozen `emptyAttributionTotals()`)
   as `usage` in the `within` outcome for a tenant with no usage. A caller that
   mutates `outcome.usage` would corrupt the shared zero for all subsequent
   evaluations. Mitigated by pure-module discipline and by the ledger's frozen
   records, but freezing the returned usage (or returning a fresh object) would
   make the fail-closed surface airtight. Owner: phase 26 (metering).
2. **F-093-2 (low): unparseable `at` without a declared period is placed
   without a temporal defect.** `rollUpCosts` only parses `record.at` when a
   period is declared; with no period, a malformed valid time is attributed
   with no temporal defect. This matches the documented contract (a temporal
   coordinate is required only when a period bounds it) and upstream ingestion
   (`UsageLedger.recordUsage`) rejects malformed `at` fail-closed — but a raw
   caller bypassing the ledger loses that gate. Worth documenting on the
   contract header or validating `at` unconditionally. Owner: phase 26.
3. **F-093-3 (info): global fail-closed scope.** One defective record refuses
   quota evaluation for ALL tenants (integrity is roll-up-global). This is
   correct fail-closed behavior (proven by test) and should be noted in
   operations: a single bad record blocks enforcement fleet-wide until
   attribution is repaired.
