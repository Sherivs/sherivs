# H3-006 Report — Backup-Expiry Strategist (J-042), Mission A-006

## Implemented

`architecture/adr/ADR-011_BACKUP_EXPIRY_DISCIPLINE.md` — a PROPOSED ADR reconciling personal-data erasure/retention (ADR-005 tombstone law; RETENTION_POLICY_SCHEDULE / ADR-005 references) with backup lifetime. Core ruling: backups cannot honor per-record erasure; erasure reaches backups **through time, never through mutation** — manifest-bound `expiresAt` ≤ the earliest retention deadline among contained personal-data families (binding ADR-008's B-1..B-4), flat TTLs forbidden, backup reads through the redaction layer (B-3), restore re-applies redaction state (B-4), expired-copy destruction ruled non-destruction. Three options considered (erasure-by-mutation — rejected as a §28 mutation path that destroys backup evidentiary integrity; crypto-shred-scoped backups — rejected per ADR-005's KMS deferral, retained as shred-class future hardening; temporal expiry — ruled). Explicit residual risk stated and bounded (post-erasure persistence in existing artifacts until `expiresAt`; sharpest instance: biometric consent-withdrawal immediacy vs backup expiry) with named owner: phase 21 (J-042, V1CAP-074), with phase 14 (schedule numbers), phase 09 (copy-destruction ≠ record destruction), and the verify pipeline (E-1..E-4/B-4). Format follows ADR-010 (field table, Context, Options, Recommendation, Golden Questions, UNKNOWNs) plus a Consequences summary.
