# H3-022 (J-036) — Injection Defense Engineer — §42 Report

Mission B-022: prompt-injection / malicious-artifact defense contracts.

## Implemented

`frontend/src/lib/security/injection-defense.ts` — pure, typed, fail-closed contracts encoding the §21 posture (AI output untrusted by default):

- **Typed content screening** (`screenContent`): bounded rule catalog (`INJECTION_RULE_CATALOG`, 12 typed rules) covering instruction-override, prompt-extraction, credential-exfiltration, action-forcing, tool-call-forgery and delimiter-manipulation patterns. Matches record rule id / category / severity / position only — never the matched hostile text, so attacker content cannot be laundered into results, audits or logs (§29). Fail-closed: control-character obfuscation blocks outright; severity ≥ `BLOCKED_SEVERITY_THRESHOLD` (4) blocks; lower severities flag.
- **Untrusted-content marking** (`markUntrustedContent`, `envelopeUnusableReason`, `isEnvelopeUsable`): untrusted content crosses trust boundaries only inside a provenance-marked envelope fenced by machine-generated nonce delimiters. Delimiter-colliding content (contains fence syntax or the nonce) is refused (`delimiter_collision`) — it cannot be safely delimited. Envelopes expire (`ENVELOPE_FRESHNESS_MS`), detect post-marking tampering (content digest re-check), are schema-version bound, and a `blocked` screen verdict makes the envelope permanently unconsumable.
- **Quarantine semantics** (`openQuarantine`, `quarantineReleaseDecision`): hold records carry digests, lengths and verdicts — never the original text. Release requires a fresh screening pass of the SAME content (digest-matched, §12 provenance) returning `allowed`; `blocked` verdicts are terminal (`hold_permanent`), never releasable regardless of any later screening result.
- **Delimited context assembly** (`assembleScreenedContext`): the only sanctioned boundary crossing. Trusted segments must cite `system_definition` provenance and are re-screened — instruction-override or delimiter patterns in "trusted" text are trust spoofing and fail the assembly (`trust_boundary_violation`). Flagged untrusted segments are excluded and auto-quarantined; a single blocked segment fails the whole assembly (`blocked_content_present`) — no silent sanitization; stale/tampered envelopes fail (`stale_envelope` / `content_digest_mismatch`); raw unmarked untrusted content cannot enter (`envelope_shape_invalid`).
- **Malicious-artifact defense** (`screenArtifact`): executable class forbidden outright; unclassified artifacts never pass clean; archives flagged for inspection; oversize, declared-vs-actual size mismatch and checksum mismatch block (§12 integrity); payloads are themselves injection-screened with worst-verdict-wins.
- **§21 AI output posture** (`screenModelOutput`, `gateAiProposal`): model output is screened like any untrusted source and its trust class is unconditionally `untrusted` (`AI_OUTPUT_TRUST_ELEVATION_PATHS` is deliberately empty — screening downgrades, never elevates). The proposal gate enforces Proposal → Validation → Policy Check → Human Approval → Execution → Audit: unvalidated / policy-unchecked / audit-less proposals block terminally; no input exists that reaches `proceed` without human closure (there is no AI-side approval input in the contract).

Boundary: pure data + pure functions. No I/O, no vendor calls, no wall clock (all instants are caller-supplied parameters), no logging. Zod-validated inputs throughout; vocabulary composes with the reasoning-provenance digest (`digestContent`).

## Known Risks

- Pattern-based screening is a defense layer, not a complete defense: novel paraphrased injection phrasing may evade the catalog. The contract is designed to compose with policy checks, human approval (B-020) and egress enforcement (C-025); it should not be consumed alone.
- The catalog screens the first match per rule (no `g` flag); repeated matches of the same rule are not individually enumerated. Verdicts are unaffected (any match drives the verdict).
- `MAX_ARTIFACT_BYTES` and `ENVELOPE_FRESHNESS_MS` are module constants; making them policy-configurable is future work with an approval path.
- The AI gateway does not yet call these contracts at its boundary (this mission authored the contracts; gateway wiring is a separate integration step).
