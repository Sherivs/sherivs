# H3-041 §42 Report — AI Live Drill Engineer (mission E-041, BLK-2, GOV-P63)

## Implemented

- `scripts/verify-ai-gateway-live.drill.mjs` — credential-gated governed end-to-end
  inference drill for the BLK-2 AI gateway decision, built in the exemplar batteries'
  image (`scripts/apply-canonical-hardening.mjs`, `scripts/verify-rls-isolation-battery.mjs`):
  - `--plan` mode: fully offline plan print (no credential read, no network, no artifacts), exit 0.
  - Live mode: strictly credential-gated. Without a usable `AI_API_KEY` (missing, empty,
    or whitespace-only — mirroring the gateway's trim semantics) it exits `2` with
    `BLOCKED_NO_CREDENTIAL` BEFORE any network contact: no endpoint resolution, no socket,
    no artifact. Configuration gaps (`AI_DRILL_MODEL` absent, non-https/credentialed
    `AI_GATEWAY_URL`) also exit `2` before any contact (`BLOCKED_NO_CONFIGURATION`).
  - With the credential it performs exactly ONE governed inference through the AI gateway
    path (`AI_GATEWAY_URL` + `/chat/completions`, the endpoint declared by
    `frontend/src/lib/ai-gateway.server.ts`): §27 discipline — authenticate, resolve fixed
    drill context (`tenantRef=control-plane/drill`, `purpose=classification` from the
    usage-ledger vocabulary), authorize (runbook citation), validate, execute (one POST,
    `max_tokens=16`, fixed non-personal prompt, 60s hard timeout, no retry, no fallback),
    audit, return permitted data. Usage counts + sha256 output digest only; the raw
    completion text is withheld (§21 output trust). Every emitted line/field is scrubbed
    against the live key (Part 29 defense in depth). Evidence:
    `ai-gateway-live-drill.json`/`.log` in `COREGRID_ARTIFACTS_DIR`.
  - Exit codes: 0 PASS/PLAN_OK · 1 DRILL_FINDING · 2 BLOCKED_NO_CREDENTIAL /
    BLOCKED_NO_CONFIGURATION / BLOCKED_USAGE.
- `docs/runbooks/ai-gateway-live-drill.md` — operator-grade drill procedure: golden
  questions, mode/exit-code contract, preconditions, the governed inference steps, what
  PASS proves and does not, evidence slots, failure handling (incident-lockdown
  escalation), explicit non-goals. Live path is marked GOVERNED NOT EXECUTED.
- `tests/unit/h3-041-ai-drill.test.ts` — OFFLINE gate tests only (10 tests): exit-2
  credential-gate semantics (absent/empty/whitespace key; incomplete configuration),
  no-network-without-credential (blocked paths emit no invocation markers, no evidence,

## Security Validation

- Fail-closed gate ordering proven by tests: argument validation → credential gate →
  configuration gate → (only then) any network contact; every pre-contact failure exits 2
  with zero artifacts and zero invocation markers.
- Secret hygiene: sentinel-credential tests prove the key value never reaches stdout,
  stderr, or artifacts on any exercised path; the script scrubs all emitted strings
  against the live key; provider bodies are truncated and scrubbed; raw completion text is
  never emitted (§21). Only secret NAMES appear in code, logs, and docs.
- No credential was present in this environment; no live inference was attempted by the
  author. The test fixture endpoint uses the RFC 2606 `.invalid` TLD and the credential
  gate fires before any URL resolution regardless.
- No `any`, no `z.any()`, no new dependencies; typed test fixtures only.

## Known Risks

- The live-mode response contract is asserted against the OpenAI-compatible
  chat-completions shape (`choices[0].message.content`, `usage.prompt_tokens/
  completion_tokens`) that the gateway's provider factory targets; a future gateway
  transport change (e.g. streaming or a different envelope) would require updating the
  drill's response contract, not its gate semantics.
- `--plan` is a static declaration: it proves the plan, not connectivity. Connectivity is
  intentionally proven only by the credentialed live run under operator control.
- The live drill performs one billed, non-idempotent call; cost is bounded by
  `max_tokens=16` and the 60s timeout, but an operator window + cost acknowledgment are
  still required (runbook §3).
