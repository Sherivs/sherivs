## Implemented

`frontend/src/lib/reality-os-kernel/contracts.ts` — the typed, fail-closed, domain-neutral CONTRACT module for the phase-51 substrate surface: the kernel COMPOSITION layer that composes universal kernel objects, relationships and events into one declared, entry-addressable kernel unit.

- **Composition declaration** (`compositionDeclarationSchema`, `parseCompositionDeclaration`): Zod strictObject schema for the composition-graph record — schema version (MAJOR.MINOR), composition id, ONE tenant scope, a governed entry key, a composition-level canonical envelope, and 1–`MAX_COMPOSITION_MEMBERS` (256) discriminated members of kind `object` | `relationship` | `event`. Fail-closed cross-member law: duplicate member keys, dangling relationship endpoints, endpoints bound to non-object members, self-referential relationships, non-object entry keys and cross-tenant provenance origins are all rejected with typed reasons; a failed parse never yields a partial declaration.
- **Composition plan** (`composeKernelUnit`, `composeFromUntrusted`): composes a parsed (or untrusted) declaration into a `ComposedKernelUnit` using the phase-33 kernel substrate's own fail-closed draft builders (`entityDraft`, `eventDraft`, `relationshipDraft`) and envelope machinery (`validateKernelObjectEnvelope`, `stampKernelDraft`) imported READ-ONLY from `frontend/src/lib/kernel/reality.ts`. All-or-nothing: substrate rejections map to typed `substrate_rejected` failures and NO partial unit escapes. Composition law enforced structurally:
  - **Composition is not authority** (phase-51 boundary): the module returns no authorization decision, grants nothing, bypasses nothing; the boundary statement `COMPOSITION_BOUNDARY_STATEMENT` is exported and pinned.
  - **No anonymous composition** (J-001): the composition-graph record and EVERY member carry the canonical CoreObject envelope, validated through the substrate validator; provenance origin tenants must match the composition tenant (§13).
  - **Object-type allowlist gating** (MISSION-R-11): `knownObjectTypes` gates every envelope — an EMPTY allowlist rejects every member type (fail-closed bootstrap); omitting the parameter defers to the substrate's live registry snapshot via `canonicalKernelObjectTypes()`.
  - **No fabricated identity** (§9 canonical truth): member objects are composition-local keys, never persistent ids; composed relationship drafts deliberately OMIT `source_entity_id`/`target_entity_id` — the plan structurally cannot be inserted until the server write path resolves keys to ids.
  - Tenancy is owned by the composition frame: member drafts cannot declare `tenantId` or a second `envelope` (strictObject rejects).
- **Governed entry resolution** (`resolveComposedEntry`): the entry point resolves only to an OBJECT member; unresolvable entries fail closed.
- **Composition invariants** (`evaluateCompositionInvariants`): seven invariant checks (`composition_stamped`, `single_tenant_scope`, `no_anonymous_members`, `explicit_causation_root`, `relationship_endpoints_resolved`, `entry_resolvable`, `bounded_unit`) reported as a typed, defense-in-depth report for units arriving from any path.

Purity: no I/O, no persistence, no vendor imports (only `zod` + the kernel substrate modules named in the mission), no wall-clock reads (every instant is a supplied parameter), no secrets. No sibling H3 module imported.

## Security Validation

- Fail-closed defaults everywhere: empty allowlist ⇒ every composition rejected; failed parse ⇒ no value; failed compose ⇒ no partial unit.
- Tenant isolation (§13/§16): one tenant scope per composition; member drafts cannot declare tenants; cross-tenant provenance rejected at parse AND compose; stamped rows carry the composition tenant.
- No authorization surface: the module never returns ALLOW/DENY and cannot open access; composition is a plan, not a grant (phase-51 boundary, pinned by test).
- No identity fabrication (§9): endpoint columns structurally absent from relationship drafts; member keys are not ids.
- Envelope law (J-001, MISSION-R-11, MISSION-R-10): every persistent-bound record stamped and registry-gated; explicit causation roots required.
- Secrets: none handled, none needed.

## Known Risks

- `z.string().datetime()` is not used here; the module defers instant validation to the substrate — consistent with the kernel substrate's own timestamp law.
- Composed relationship drafts intentionally cannot be inserted without endpoint resolution; if a future consumer attempts a direct insert, the database FK constraint is the next fail-closed layer — the server write path must implement key→id resolution (documented in the module).
- The module does not deduplicate semantically identical members — composition identity is by declaration, canonical dedup belongs to the event/idempotency substrate.
