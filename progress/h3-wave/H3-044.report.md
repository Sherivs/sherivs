- **Live mode (default)** — strictly gated, in order, ALL gates before any network contact: (1) unknown args / undeclared provider id → exit 2 `BLOCKED_USAGE`; (2) missing `COREGRID_COMMUNICATION_PROVIDER_CREDENTIAL` → exit 2 `BLOCKED_NO_CREDENTIAL` ("Nothing was probed and no network contact was made"), nothing further runs; (3) offline rehearsal must pass (any finding → exit 1, still zero network); (4) missing `COREGRID_COMMUNICATION_SANDBOX_TARGET` → exit 2 `BLOCKED_NO_SANDBOX_TARGET` — the drill REQUIRES an operator-supplied sandbox verification target by design, so without one there is no authorized destination and no contact; (5) target validation (must be `https://`, no embedded credentials) → exit 2 `BLOCKED_SANDBOX_TARGET`; (6) exactly ONE read-only verification handshake: GET, no message payload, response body never read or written, redirects refused (`redirect: "error"` — a redirect could carry the credential to an unapproved host), 8s timeout (parity with `DEFAULT_EMAIL_FAILURE_POLICY.timeoutMs`), bearer credential to the sandbox target only. 2xx → exit 0 · anything else → exit 1.
- **Send-nothing-real law**: the probe never sends any message/email/SMS/push/voice/meeting/social content; it consumes the communication/notification server modules through their DATA contracts only (record-only stub adapter `NOT_FOR_LIVE_USE` is the provider path's read-only consumption pattern — proven in tests to resolve every send to `undeliverable("provider_not_configured")` even when a registry claims the provider is configured).
- **Secret hygiene**: secret NAMES declared (`COREGRID_COMMUNICATION_PROVIDER_CREDENTIAL`, `COREGRID_COMMUNICATION_SANDBOX_TARGET`); values never printed, logged, or written — including error paths; sandbox target recorded as host only; live artifacts record `credentialPresent: true` (boolean), never the value.

## Security Validation

- Fail-closed credential gate fires BEFORE any other live work and before any network contact — verified structurally (gate order in code) and by test (exit 2 with no artifact, and fires even with a target present).
- Dual-destination law: a live run requires BOTH a credential AND an operator-supplied sandbox target; without either, exit 2 with zero contact. The probe has no built-in destination.
- One read-only GET, no payload, redirects refused, response body never read/persisted, 8s timeout; https-only, embedded-credential URLs refused.
- Secret values never printed/logged/written (sentinel-asserted); only secret NAMES and booleans appear in artifacts; host logged, never the full URL.
- Send-nothing-real enforced at three layers: plan schema (no send kind; only handshake may be networked), catalogue lifecycle (all external providers DISCOVERED — routing refuses), and the notification pipeline's record-only stub adapter (NOT_FOR_LIVE_USE, never delivers).
- Offline rehearsal provably contacts nothing; live artifacts record `sendCapable=false`.

## Known Risks

- The live handshake proves sandbox reachability + credential acceptance of a verification path only; it does not prove end-to-end delivery (that requires a genuine provider receipt, which this probe must never fabricate). Documented in the runbook §7.
- The embedded catalogue mirror must stay in lockstep with `frontend/src/lib/communication-providers.ts`; the unit suite deep-cross-checks it and fails loudly on drift, but the mirror is a deliberate duplicate (the .mjs cannot import the TS module without a loader).
- Per-provider handshake semantics are intentionally generic (operator supplies the sandbox target) to keep the drill provider-agnostic (§25); a per-provider drill would need an ADR.
- No live run has been performed, so the handshake path's runtime behavior (e.g., provider-specific verification endpoints) is untested by construction — honestly GOVERNED NOT EXECUTED.
