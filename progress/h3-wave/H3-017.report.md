## Implemented

Authored `frontend/src/lib/agent-runtime/capability-matching.ts` — the capability-overlap matching depth between **declared capabilities** and **required capabilities**, fail-closed on unknown capabilities, composed read-only with the existing agent-runtime neighbors:

1. **Zod-validated vocabulary (strict shapes).** `capabilityDeclarationSchema` (`capabilityId` + `description`, matching the `WorkerCapabilityDeclaration` shape), `capabilityRequirementSchema` (`capabilityId` + `purpose` provenance of the demand), and `capabilityRegistrySchema` (bounded at 1024 declarations; strict objects reject unknown keys). Capability ids are trimmed, non-empty, ≤160 chars, control-character free.
2. **Fail-closed registry parsing.** `parseCapabilityRegistry(input: unknown)` yields `ok: false` with structured issues on any shape violation or cross-record invariant (duplicate declared capability ids); a failed parse never yields a partial registry. An **empty registry is valid and has zero authority** (untrusted by default). `capabilityRegistryFromDeclarations` builds the registry view over typed declarations.
3. **THE capability-overlap match (`matchCapabilities`).** Exact-set overlap only: a required capability is covered when, and only when, an identical declared id exists — **no fuzzy, prefix/substring, or case-normalized matching, no inheritance, no defaults**. Results:
   - `ok: true` only at depth `full` (every requirement declared);
   - `ok: false, code: "unknown_capability"` with the exact uncovered ids enumerated and matched ids reported — depth is `partial` (some overlap) or `none` (nothing overlaps); a partial match is **reported but never authorizes**;
   - `ok: false, code: "empty_requirements"` — an empty requirement set denies rather than trivially passing (mirrors the delegation law "a delegation grants at least one action");
   - `ok: false, code: "duplicate_requirements"` — duplicated requirements deny instead of being silently deduplicated (silent dedup could mask a caller bug on exactly the surface that computes authority).
4. **Delegation-contract composition (read-only).** `delegationCapabilityBound(MissionDelegation)` extracts the structural `DelegationCapabilityBound` view (`delegationId` + `grantedActions`); `matchDelegationCapabilities` requires every granted capability to overlap the declared registry, fail closed on unknowns. The delegation contract's own laws (non-escalation, expiry, revocation, tenant/mission scope) remain owned there and are never relaxed here.
5. **Worker-definition composition (read-only).** `matchWorkerCapabilities(WorkerDefinition, required)` denies with `definition_lifecycle_unusable` **before any overlap is computed** when the definition lifecycle is not usable (suspended/archived/deleted — the same `isIdentityUsable` predicate the identity model enforces); a zero-capability definition matches nothing (zero authority).

Pure contract module: no I/O, no persistence, no wall-clock reads, no vendor imports, no execution. Strict TypeScript, no `any`/`z.any`, Zod at the untrusted-input boundary, neutral vocabulary only (J-037), no new dependencies (Zod already a repo dependency).

## Security Validation

- **Fail closed on unknown capabilities:** every unmatched requirement denies the whole match with `unknown_capability` and enumerates the exact uncovered ids; the deny detail states no partial/fuzzy/case-normalized coverage exists (tested, including near-miss ids and case variants).
- **No authorization by partial match:** depth `partial` is observability only — the result type makes it impossible to mistake a partial overlap for a pass (`ok` is `true` exclusively at depth `full`).
- **Nothing from nothing:** empty requirement sets and empty declared registries both deny; a zero-capability definition has zero matchable authority (untrusted by default, AGENTS §5).
- **Ownership boundaries preserved:** the matcher adds restrictions only — delegation lifecycle/expiry/tenant/mission enforcement stays in `delegation-contract.ts`; claim-time capability-subset and risk-ceiling enforcement stays in `claimWorkerRuntime`; lifecycle usability reuses the identity model's predicate rather than redefining it.
- **Untrusted-input boundary:** all registry/requirement inputs pass Zod strict validation; envelope-bearing delegation fixtures are built through the existing fail-closed stamping API, never hand-forged.
- No git commands run; no database or network access; no secret values printed, logged, or written (all fixtures are synthetic literals; the module has no secret-bearing surface).

## Known Risks

- This module computes the capability dimension only; it does not (and must not) replace `evaluateDelegationAsOf` / `authorizeDelegatedAction` (lifecycle, time window, tenant, mission) or `claimWorkerRuntime` (subset + risk ceiling). Callers must compose all layers; a deployment that calls only this matcher gets capability-overlap enforcement only.
- Matching is exact-id by design; capability ids that differ in case or wording are "unknown". Registries should be curated with canonical ids (the parse layer bounds sizes but normalizes nothing else).
- O(n·m) set matching is fine at the bounded registry size (≤1024); a set index would be warranted only if registries grew unboundedly.
