## Implemented

`frontend/src/lib/observability/metrics-registry.ts` — a PURE, fail-closed typed metrics registry:

- **Typed metric families**: Zod (`strictObject`) declarations for `counter` / `gauge` / `histogram` (`bucketsMs` with strictly-increasing bounds + implicit `+Inf` overflow slot). Counter accumulates, gauge holds the latest finite value, histogram maintains per-bucket counts, `count`, `sum`.
- **No PII / no secrets in labels, enforced by schema** (Constitution §19/§29/§30): every label value passes `isSafeMetricLabelValue` — a deny-by-default structural gate (tight charset `[A-Za-z0-9_.:/%+-]`, length ≤ 64, plus secret-shaped detectors: token prefixes `sk_/ghp_/xox-/AKIA…`, JWT segments, PEM armor, long base64/hex blobs, credential carriers `password|secret|token|api_key|bearer|authorization…[:=]`, and identifier-shaped values: UUIDs, emails, long digit/hex runs, opaque tokens ≥ 25 chars). Rejected values are never echoed back — rejection details stay content-free so a rejected secret cannot leak through the rejection path.
- **Bounded cardinality**: ≤ 4 label keys per metric, ≤ 16 buckets, per-metric series ceiling (default 64) and registry-wide series ceiling (default 256), enforced as typed rejections (`cardinality_exceeded`, `series_cap_exceeded`), never silent absorption.
- **Fail-closed on unknown metric names**: closed vocabulary — observation against an undeclared name is a typed `unknown_metric` rejection, counted in a rejection ledger, never recorded and never thrown. Also typed rejections for `unknown_label_key`, `missing_label`, `label_value_rejected`, `invalid_value` (non-finite / negative counter), `invalid_declaration`, `duplicate_metric`. Injectable `onRejection` observer carries codes only.
- **Composition, READ-ONLY**: `substrateTelemetrySamples(snapshot: SubstrateTelemetrySnapshot)` and `healthCheckSamples(report: HealthReport)` map the existing modules' outputs into recordable samples; `CORE_METRIC_DECLARATIONS` ships the matching closed metric vocabulary. Neither source module was modified; no new dependencies; Zod already present.

## Known Risks

- The safety gate is structural (deny-by-default), not semantic: a benign-looking-but-actual-secret value that fits the charset could still pass (e.g., a low-entropy word chosen as a secret). Defense-in-depth: labels are operator-declared keys with bounded vocabulary; F-052 (log redaction) is the adjacent sweep.
- The opaque-token detector (`[A-Za-z0-9_-]{25,}`) also rejects long benign opaque strings (e.g., a 30-char deployment id) — intentional fail-closed bias; such values belong in traces, not labels.
- `DEFAULT_MAX_SERIES_TOTAL` (256) is a module default; production adoption should size it per deployment.
