   - **`UNIQUE (tenant_id, idempotency_key)`** — the durable exactly-once arbiter: under a retry/concurrency race exactly one record wins (database-enforced, not application-enforced — AGENTS §17/§28).

   - **Posture entry recorded as a SQL header comment** (per mission law) — the posture JSON files were NOT touched.
   - Payloads are never persisted (only the SHA-256 digest — minimization, §19); no secret values anywhere.

Same semantics, lifted to the async persistence boundary: `get` returns null for absent-or-expired (fail-safe), `put` is atomic per key (`ON CONFLICT (tenant_id, idempotency_key)` — first record for a live key wins, expired rows replaceable atomically), `prune` deletes expired rows and returns the count. Tenant-scoped in every statement (independent layer on top of RLS, §17); injected minimal query client, no credentials; strict TS, no untyped escapes; provider/mapping failures are thrown (`IdempotencyStoreDbError`) and are NEVER conflated with "absent" — a DB failure can never silently degrade into a fresh execution.

## Security Validation

- **RLS**: FORCE RLS; SELECT tenant-equality via `get_my_tenant_id()` (unbound actor → NULL → zero rows; AMBIGUOUS_TENANCY raises — fail-closed); INSERT/UPDATE re-derive actor from `auth.uid()` — no client-supplied tenant/actor/role can satisfy a predicate; DELETE has no policy and authenticated holds no DELETE privilege.
- **Mandatory battery invariants**: Tenant A cannot read/replay Tenant B's records (tested at store level; RLS probe is the battery's job post-apply); expired access fails (TTL filter tested); no agent/client path can rewrite a LIVE recorded outcome (replace-expired-only UPDATE, tested); revocation semantics inherited from the primitives' time-bounded role checks.
- **Exactly-once durability**: `UNIQUE (tenant_id, idempotency_key)` + first-record-wins arbitration is database-enforced; the store's `put` never overwrites a live record even under a mock-emulated race.
- **Least privilege / minimization**: only the payload digest is stored, never payloads; `response_ref` is opaque; no secrets printed, logged, or written anywhere.
- **Application code is not the only layer**: tenant scoping in SQL statements is defense-in-depth beneath the RLS policies, never a replacement for them.

## Known Risks

- The migration is AUTHORED, not applied — the RLS/battery claims are verified statically against the exemplar conventions and at store level offline; live proof requires the coordinator's serialized canonical apply (campaign law 5).
- The `IdempotencyStore` contract is synchronous (in-memory reference); the durable variant is its asynchronous image (same names, semantics and record shape) because DB I/O is inherently async. Consumers wanting `executeIdempotent`-driven replay with the durable store load the record via `get` and hand it to the contract (exactly what the restart test does); a future sync facade was deliberately not faked.
- Expiry-vs-prune window: between expiry and the next prune run, an expired row still occupies its key slot; replacement is handled atomically by the replace-expired conflict clause, so no correctness gap — only transient storage retention.
