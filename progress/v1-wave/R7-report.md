   - **AUDIT** — every launch attempt (denied / blocked / launched) writes a fail-closed audit record via `writeAuditRecord` (action `workforce.launch_worker_mission`, gate `requirePlatformSuperAdmin`, WHO resolved exactly like the provisioning family — canonical users row, else verified email claim), no secrets (§29/§30).
   - **TYPED OUTCOMES** (§16 decision vocabulary as data, never a fake success):
     - `{ outcome: "denied", code: "gate_denied" | "invalid_request" | "execution_not_found" | "worker_not_launchable" }`

   - Every returned outcome carries the persisted audit row **intent** (`audit`), so the UI shows the record without re-deriving it and no attempt can pass unaudited.

## Security Validation

- **Backend enforcement (§34):** gating lives in the server function (`requirePlatformSuperAdmin`), proven behaviorally against the real gate code (tests drive the actual `resolveRoleGate`/`assertRoleScope` path); the UI guard only shapes navigation.
- **Fail-closed credential law:** no `AI_API_KEY` ⇒ typed `BLOCKED_NO_CREDENTIAL` **before** any wake, lease acquisition, or provider contact; a fake success is impossible by construction (asserted: zero lease attempts in the blocked state). The gateway re-checks the credential itself (`unconfigured` deny) as a second gate.
- **Tenant boundary (§13/§26/§31):** the tenant field is a validated target scope checked against the registry substrate (definition `tenantScope` must match); cross-tenant reads return the same not-found signal (no existence oracle); no client role/tenant assertion is ever trusted.
- **Audit (§27.6/§29/§30):** every attempt writes a fail-closed record; WHO resolution matches the provisioning family; details carry outcome codes, ids and bounded reasons only — test asserts no secret-shaped material in the audit intent.
- **Least privilege of the launch itself:** the worker's authority is re-resolved at WAKE through `buildWorkerMissionActor` (escalation denied, never clamped; revocation/quarantine effective at the next gate).
