A generic model or test is not evidence that the corresponding Scholar workflow is delivered. The coverage column records current artifacts only; **all additional Phase 12 implementation in this epic is V2-frozen** under the current repository classification. Existing legacy timetable functionality does not authorize extending Phase 12 as V1.

- **Built** — the requested V1 capability is integrated and meets the stated requirement.
- **Partial** — relevant artifacts exist, but an integration, safeguard, or requested user-facing behavior is missing.
- **Missing** — no implementation of the requested capability was found; related foundations are called out separately.
- **V2 (deferred)** — frozen scope, not authorized for implementation without an explicit human unfreeze/reconciliation record. For this matrix, every requested Phase 12 capability is gated V2.

## S0 result and phase disposition

**S0 coverage inventory:** 0 built, 7 partial, 3 missing. **Version gate:** all additional Phase 12 implementation needed to meet the ten requirements is V2-frozen under the current classification; coverage labels describe extant artifacts and do not authorize extending them. Existing legacy timetable behavior remains unchanged.

The scheduling domain has useful generic foundations: deterministic conflict detection, constraint and availability models, quality/explanation logic, generic calendar/recurrence types, and some existing Scholar timetable and exam persistence. The principal gaps are the school-wide solver and its job lifecycle, secure/versioned scheduling persistence, workflow wiring, and user-facing editing and views.

The issue's S1–S5 sequence is a proposal only. Do not start implementation PRs until an authorized human records the scope reconciliation/unfreeze and the repository's Phase 12 V2 classification is resolved:

1. **S1 — data model and solver core:** resolve the neutral tenant key and forced-RLS design first; persist scheduling inputs and versions; add the deterministic, seedable solver and focused constraint tests.
2. **S2 — builder and conflicts:** implement manual edits, validation, conflict explanations and suggested fixes.
3. **S3 — role views and offline:** provide authorized admin, teacher, student and parent views, then wire timetable reads into the existing per-user offline cache.
4. **S4 — rescheduling and exams:** add governed rescheduling proposals and close the exam clash/resource gaps.
5. **S5 — verification:** add hard-constraint/property tests, the specified simulated-school performance test, and an evidence report.

The twin hook is also V2-frozen and requires Phase 16/Reality Intelligence owner review. No V2/V3 implementation, migration, or progress claim is made by this matrix.
