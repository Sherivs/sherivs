## Implemented

- Seven closed V1 action kinds, the six-category `draft` cap, a 25-recipient mass threshold,
  confidential/minor-sensitive classification, and fail-closed delivery-mode parsing.
- Broker-first effectful action dispatch with step idempotency, tenant-local recipient lookup,
  approved-template checks, registered HTTPS webhook validation, and server-only draft/outbox
  persistence.
- SQL catalogue, action drafts, sandbox outbox, webhook target registry, forced RLS, service-role
  writes, autonomy trigger caps, and rollback.
- Unit policy/dispatcher tests, local SQL cap/grant/RLS/cross-tenant checks, and
  `tools/sim-lab/load/wf06-action-e2e.mjs`: real Postgres + PostgREST ticks through the production
  executor (only provider adapters stubbed, with call counters) for sandbox in-app delivery, a
  capped 26-recipient SMS draft, staging live refusal and same-key retries.
- Delivery mode and emergency stop guidance in the workflow enablement runbook.

## Validation and operational boundary

- The WF-06 SQL integration uses a transaction and rolls back. The migration and E2E run only in
  the disposable local sim-lab and CI.
- No hosted database has been touched, no deployment has been performed, and no organization has
  been enabled by this implementation.
- Live delivery remains fail-closed when a supported broker adapter, active binding, or secret
  resolver is unavailable. The current server executor does not install email, SMS, WhatsApp,
  in-app, or webhook adapters. `task` and `wait` can be broker-ledgered and sandboxed but have no
  live handler. These paths must not be described as production-ready.
- WF-07 owns the human approval inbox. Drafts are not executed.
