## Objective

Staff review an onboarding request (answers read-only, generated plan, plan diff, edits), approve it with a passkey bound to the request and plan hash, and provision the organization from the approved plan in ONE database transaction, idempotently, with a complete audit trail and the self-serve flag OFF.

## Acceptance (brief §12.1 M6)

| Criterion                              | Evidence                                                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Same plan twice is idempotent          | SQL: second run returns first result, footprint and audit count unchanged                                                                                    |
| Failure leaves no partial tenant       | SQL: injected failure after root, kernel, console, profile, units and pack; invalid website draft; unpublished pack: zero rows in 11 tables, zero audit rows |
| Complete audit trail                   | DB audit rows for assign, generate, edit, approve, provision; tenant rows via `scholar_audit`; app-level audit for every outcome incl. refusals              |
| Self-serve flag OFF                    | Seeded `false`, locked; service role cannot switch it; `self_serve` channel refused                                                                          |
| Stale plan hash refused                | SQL and unit: approve and provision refuse old hash; step-up challenge for another hash refused before any write                                             |
| Non-staff and tenant users cannot call | SQL: anon, authenticated tenant user and staff with own JWT have no EXECUTE; server cannot act for a tenant user or suspended staff                          |
| Rollback                               | SQL: rollback removes everything; provisioned organization stays intact; re-apply works                                                                      |

## Founder decisions

1. Editor-cannot-approve is enforced in the database; with one staff identity an edited plan needs a second staff member.
2. No institution role pack is published yet, so nothing can be provisioned until one is (placeholder packs are refused).
3. `cg_tenant.environment` keeps the column default (`development`); choose the production value.
4. Super-admin alone does not grant `platform.tenants.manage` (existing console rule); the founder needs the operations role on his staff row to approve.
