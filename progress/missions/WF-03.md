## Implemented

- `/api/public/cron/workflow-tick`:
  - `CRON_SECRET` bearer checked in constant time; 503 until it is configured, 401 otherwise;
  - global `WORKFLOWS_ENABLED=true` switch (otherwise it claims nothing);
  - 45-second budget; the response carries counts only.
- Runtime ports: a pure tick loop over `workflow-engine.ts`, a Supabase service-role port, and an in-memory port for tests.
- Reliability:
  - exponential retry with bounded jitter;
  - step timeouts;
  - dead after the maximum attempts;
  - run deadline gives `timed_out`;
  - effects recorded in `cg_idempotency_record`.
- Per-step budget: an effect that would exceed it goes dead with `budget.exhausted` and is not executed.
- OpenTelemetry spans for the tick, claims, run advance and step execution (ids, counts and codes only).
- Post-commit kick helper: https only, 3-second timeout, never throws.
- Schema:
  - `wf_template` gains agent, autonomy ceiling, release, risk tier, organization types, data classes, lawful basis, eval suite and changelog; the existing rows are set to `suggest`, `needs_integration` and `high`;
  - `agent_ref` on runs and steps;
  - per-step autonomy level, action class and budget;
  - `wf_org_settings`: forced RLS, read with `workflows.view`, write with `workflows.manage`;
  - `wf_agent_autonomy`: service role only;
  - `wf_claim_due_events`; `wf_claim_due_steps` now honours the organization switch and run deadlines;
  - `wf_create_event_run` and `wf_persist_step_transition` (invoker, service role only);
  - settings changes are audited.
- Autonomy:
  - The effective level is the lowest of the template ceiling, the tenant setting and the agent's earned level. A database trigger enforces it on every step insert and update.
  - Only `internal` steps can go above `draft`. Money movement, safeguarding, credential changes, public publishing, mass messages and sharing with an external authority stay at draft or lower.
