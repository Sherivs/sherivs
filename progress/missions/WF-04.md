## Scope and safeguards

- The existing wallet reconciliation route remains enabled by default; all other production route
  settings default off.
- Staging config enables only `workflow-tick` and uses a deliberately non-routable target
  placeholder. An operator must replace it with an HTTPS staging deployment URL before staging
  use. It must never point at production.
- `CRON_SECRET` is a Worker secret. Cloudflare account credentials are supplied only in the
  deployment environment. Preview URLs are disabled.
- Production `WORKFLOWS_ENABLED` remains unset, and no organization is enabled.
- The local load runner mints its service-role JWT from the sim lab's generated local signing key,
  rewrites Supabase REST paths to the loopback PostgREST root, and refuses non-loopback Postgres
  and non-local PostgREST requests. Synthetic fixtures are removed after the run.
- The staging SQL throughput probe is guarded by the WF-02 staging marker and absence of
  `payment_intents`. Its final exception reports results while rolling back all fixture rows.

## Validation

The Worker unit tests cover UTC cadences, disabled settings, HTTPS-only targets, manual bearer
verification, route selection, failure isolation, redacted logs, and timeout aborts. The sim-lab CI
smoke runs the actual `runWorkflowTick` and server port against local PostgREST and checks for
positive step throughput and zero duplicate executions.

Results are generated under `tools/sim-lab/results/wf04-workflow-tick-*.json`; generated result
files are not source artifacts. No Worker deployment or hosted SQL execution is part of this
mission.
