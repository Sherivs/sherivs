Active persona: Principal Frontend Engineer, with the Postgres and RLS Security Engineer.

## Objective

Every card the shell can open at `/home/s/<key>` resolves through one typed registry. Real screens stay real; every other catalogue card shows an honest planned state; unknown keys show not-found. The catalogue's dead portal routes move to shell routes through a reversible migration.

## Reconnaissance

- Production `public.workspace_item_catalog` (read-only SELECT, 2026-11-17): 107 rows, columns key, kind, route, any_permissions, all_permissions, feature, size, label_en, families, sort, scope_dims, policy. The md5 of its `key|kind|route` rows equals the client mirror `frontend/src/lib/sherivs-ws/catalog.data.ts`, so the mirror and production agree. Grants: `authenticated` SELECT only, `anon` nothing, `service_role` all.
- `section-screen.tsx` rendered real screens for `roles`, `agents`, `role-packets`, `workspace-policies`, `school_setup`, `communications`, `students`, `nav.students`, `nav.reports`. No privacy register screen exists on master.
- 29 widgets get real figures from UX3 (`shell.cards`); the planned state keeps showing those figures, labelled as read from records.
- `uniqueCatalogItems` deduplicates cards by route and `permittedNotificationLink` matches legacy routes, so moving routes would change both unless the legacy destination is kept on the client.

## Scope and file boundaries

`frontend/src/lib/shell/**` (new `card-registry.ts`, `planned-capability-copy.ts`; `chrome.ts` reads legacy provenance), `frontend/src/components/app-shell/section-screen.tsx`, new `frontend/src/components/app-shell/planned-capability-state.tsx`, migration and rollback `20261117001200_sherivs_m3_workspace_item_routes`, `tests/sql/m3-workspace-item-routes.sql`, new unit tests, `tests/fixtures/workspace-item-catalog.snapshot.json`, ADR-106 and its INDEX row, this file.

## Data changes

`workspace_item_catalog.legacy_route text NULL` (new column, inherits the table's privileges); `route` becomes `/home` for `nav.home` and `/home/s/<key>` for every other key. NOT APPLIED. Rollback restores every moved route from `legacy_route`, then drops the column.

## Risks

- Live screens now load lazily: a short "Loading…" state precedes them.
- Hiding planned cards from manifests is not implemented (ADR-106 explains why); planned cards stay visible and honest.
- After the migration the server's routes differ from the generated client mirror; `catalogueProvenance` relies on the mirror for the legacy destination.
