## Objective

The admissions data model in the database with its rules proven: cycles, programmes, versioned forms, question
bank, screenings, append-only scores, offers with separation of duties, documents, link and tertiary columns on
`admission_applications`, and a blind scoring surface. No UI, no public routes, no payment code.

## Risks

- Revoking table-level SELECT on `admission_applications` from `authenticated` (to hide tertiary columns) makes
  `SELECT *` fail for signed-in callers. No current web or mobile code reads this table directly (repository search);
  later screens must name columns.
- Append-only scores block a cascaded delete of an application with scores (same as `admission_stage_events`).
- Forms freeze once a cycle opens, including new versions.
