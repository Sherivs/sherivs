# AIN-06a/b/c and AIN-07: companion contract and evaluation gate

Status: built (TypeScript only, no model, no database change), draft PR #530.

- `frontend/src/lib/assistant/companion-contract.ts`: one spec per role (persona, allowed source kinds, may it draft, is a human handoff required, aggregate-only for platform roles) and `checkCompanionAnswer`. It refuses an answer with no citation, a disallowed source, no stated limits, a missing handoff (family and learner), a draft from a role that may not draft (family, learner, nurse, driver), or a person-level detail in a platform answer. 06a (leaders, family, learners), 06b (teaching) and 06c (administration, operations) share one registry.
- `frontend/src/lib/assistant/companion-evals.ts`: `runCompanionEvals(answerer)` with a baseline case per role plus four trap cases. `canExpand` is true only when every case passes and every role is covered. The answerer is injected, so any model provider plugs in later (no vendor, no real calls here).
- Tests: 13 pass.
- Not built: the real answerer and model router; the JARVIS aggregate brief (ADR-142 item 3); screens; per-organisation overrides; head-of-institution role mapping per pack.
- Limit: the checker proves an answer has the required shape. It cannot prove a cited source supports the claim; that needs a human-labelled eval set once a real model exists.
