## The decision M1 cannot make alone (founder decision 2)

| Option                                                                                                                                             | What it means                                                    | Cost                                                                                                                                 | Risk                                                  |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| **A. Promote `public.schools`** as the canonical root, generalised with an institution type; `cg_tenant` and `platform_organization` map to it 1:1 | Keeps 378 policy helper calls and every Scholar policy untouched | Lowest. The name stays school-shaped in the database while the product says "organization"; views and helpers carry the neutral name | Lowest: RLS is not rewritten                          |
| B. Promote `platform_organization`                                                                                                                 | Neutral name; console already uses it                            | Every Scholar policy and helper must be repointed (thousands of references)                                                          | High: a mass RLS rewrite with no CI history behind it |
| C. Promote `cg_tenant`                                                                                                                             | Kernel-first                                                     | Same rewrite as B, plus the kernel's `tenant_ref` is not what Scholar tables key on                                                  | High                                                  |

**Recommendation: A.** The database is the security boundary, and the boundary is written in terms of `schools`. Rewriting it buys a nicer name and risks tenant isolation. Under A, M1 adds a neutral read surface (`organization` view and `get_my_organization_id()` alias), makes `school_tenant_map` the enforced 1:1 bridge (filled by provisioning in one transaction), and leaves every existing policy alone.

## Scope (after the decision)

1. ADR-102: canonical root and mapping, listing every RLS helper and how it stays compatible.
2. Mapping: make the bridge 1:1 and mandatory at provisioning; a check that no root row exists without its counterparts.
3. Unit tree: extend `workspace_org_units` with the unit kinds in §5.3; a constraint and SQL test that a unit cannot reference another organization's unit.
4. `institution_profile`: type, ownership, regulators, accreditation status, calendar model, grading system, curriculum, languages; effective-dated; RLS forced; explicit grants.
5. Speculative modules: trace importers; quarantine only modules with no path to a route, updating the guard tests that name them; delete nothing in this mission.
6. Role logic: name one canonical owner (`lib/scholar/roles` with the database functions) and add deprecation notes to the others; no behaviour change.

## Risks

- A quarantined module turns out to be reachable: mitigated by tracing importers and running the full build and E2E.
- The bridge constraint blocks provisioning: mitigated by SQL tests of the provisioning function on a disposable database.
- New tables under SEC-M0's private-by-default: every table ships explicit grants (the M0 grant check enforces it).
