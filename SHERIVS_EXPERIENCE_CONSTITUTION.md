# SHERIVS EXPERIENCE CONSTITUTION (SEC-v1.0)
**System:** Sherivs — Institutional Intelligence Infrastructure  
**Version:** 1.0  
**Authority:** Platform-Wide Autonomous Design & Frontend Engineering Governance  

---

## 1. The Prime Experience Directive

> **No surface, component, or interaction in Sherivs may optimize local aesthetic flair at the expense of global institutional clarity, accessibility, security, or architectural integrity.**

Code or design that looks impressive but violates Sherivs architectural boundaries, fabricates metrics, confuses tenant context, or degrades accessibility is considered **defective and rejected at Gate 11**.

---

## 2. Core Invariants of Institutional-Grade Design

1. **Truth Over Decoration:**
   - Every metric, progress bar, chart point, and status indicator must reflect verified database truth.
   - Fake glowing orbs, decorative particle networks, fabricated live activity streams, and simulated telemetry are strictly prohibited.
2. **Canonical Reality Separation:**
   - Always visually distinguish **Reality** (verified database truth, signed events, timestamps, actual attendance, financial records) from **Intelligence** (AI inferences, forecasts, semantic embeddings, recommendations).
3. **Sovereign Trust & Dual-Control:**
   - Critical actions (permission elevation, financial disbursements, large-scale data export, mission execution) require visible dual-control verification states and human approval gates.
4. **Predictable Motion Physics:**
   - Motion is informative, never theatrical. Transitions communicate state shifts, layout elevation, or asynchronous processing.
   - All animations must respect `prefers-reduced-motion` and collapse to zero duration or subtle opacity fades.
5. **Universal Viewport Resilience:**
   - The platform must function with complete dignity from a 360px mobile handset up to a 2560px+ multi-monitor operations room.
   - Mobile is not a degraded desktop; it is a dedicated, touch-optimized ergonomic surface.

## 3. The Ten Design Review Gates

Every experience surface must pass all 10 review gates before being merged into production:

```
┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐
│ GATE 1 │ ──> │ GATE 2 │ ──> │ GATE 3 │ ──> │ GATE 4 │ ──> │ GATE 5 │
│   IA   │     │ Interact│     │ Visual │     │Respons.│     │ A11y   │
└────────┘     └────────┘     └────────┘     └────────┘     └────────┘
    │
    ▼
┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐
│ GATE 6 │ ──> │ GATE 7 │ ──> │ GATE 8 │ ──> │ GATE 9 │ ──> │ GATE 10│
│  Perf  │     │Security│     │ Code   │     │ Tests  │     │ Conformance│
└────────┘     └────────┘     └────────┘     └────────┘     └────────┘
```

- **Gate 1: Information Architecture:** Logical entity hierarchy, natural semantic pathing, zero dead-ends, clear breadcrumb provenance.
- **Gate 2: Interaction Architecture:** Immediate affordance, keyboard navigation on every control, predictable hover/active/focus loops.
- **Gate 3: Visual Architecture:** Proprietary Sherivs depth language, strict token usage, WCAG AAA text contrast on key telemetry, zero unharmonized fonts.
- **Gate 4: Responsive Architecture:** Fluid breakpoints (360px, 390px, 430px, 768px, 1024px, 1280px, 1440px, 1920px+). Zero accidental horizontal overflows.
- **Gate 5: Accessibility (WCAG 2.2 AA+):** Screen-reader announcements (`aria-live`), focus trap in dialogs, visible 2px focus rings with contrast offsets, keyboard escape handlers.
- **Gate 6: Performance & Core Web Vitals:** LCP < 1.2s, INP < 100ms, CLS < 0.05. Zero unnecessary client bundle re-renders.
- **Gate 7: Security & Tenant Isolation:** Zero client-side tenant spoofing, no sensitive keys in client bundles, server-side authorization enforcement on all actions.
- **Gate 8: Code Quality & Types:** Strict TypeScript, Zod schema validation on all inputs/outputs, zero `any` types, clean separation of presentation and server functions.
- **Gate 9: Automated Test Coverage:** Unit test for state machine, snapshot/integration test for contract rendering, isolation tests.
- **Gate 10: Architectural Conformance:** Zero domain-contamination of the universal kernel, adherence to the CoreGrid ASI Constitution and V1 Execution Boundary.

## 4. Prohibited Design Antipatterns

The following are strictly banned across the entire Sherivs ecosystem:
- ❌ **Generic SaaS Card Grids:** Stacking cards uniformly without hierarchical weighting or IA justification.
- ❌ **The "AI Magic Wand" Cliché:** Using sparkles, purple glow fields, or generic robot icons to represent serious institutional machine intelligence.
- ❌ **Fake Testimonials / Fake Logos:** Fabricating companies, photos, or quote attributions on public surfaces.
- ❌ **Deceptive Loading States:** Showing fake indeterminate spinners when no network call or background job is running.
- ❌ **Hidden Buttons as Security:** Hiding an action button in the frontend while leaving the backend API endpoint unprotected.
- ❌ **Hardcoded School Vocabulary in the Universal Shell:** Never refer to classrooms, grades, tuition, or bursars outside the Sherivs Scholar runtime adapter.
